Save and load pipeline configurations for reproducibility and version control.

## Save

```python
from epftoolbox2.pipelines import ModelPipeline
from epftoolbox2.models import OLSModel, LassoCVModel
from epftoolbox2.evaluators import MAEEvaluator
from epftoolbox2.exporters import TerminalExporter, ExcelExporter

predictors = [
    "load_actual",
    "is_monday_d+{horizon}",
    "price_d-1",
    "warsaw_temperature_2m_d+{horizon}",
]

pipeline = (
    ModelPipeline()
    .add_model(OLSModel(predictors=predictors, training_window=365, name="OLS"))
    .add_model(LassoCVModel(predictors=predictors, training_window=365, cv=5, name="LassoCV"))
    .add_evaluator(MAEEvaluator())
    .add_exporter(TerminalExporter())
    .add_exporter(ExcelExporter("results.xlsx"))
)

pipeline.save("model_pipeline.yaml")
```

## Load

```python
pipeline = ModelPipeline.load("model_pipeline.yaml")
report = pipeline.run(data=df, test_start="2024-04-01", test_end="2024-06-01")
```

## YAML Format

[Ensembles](/epftoolbox2/model-pipeline/ensembles/#yaml) are saved in an `ensembles:` section after `models`, only if there are any.

If the pipeline has an `information_set` (see [Information Set](/epftoolbox2/model-pipeline/information-set/)),
it is saved as a top-level `information_set` key, and a level you asked for as `availability`. Left out, a load takes the
default: `warn` with an `information_set`, `none` without one. Its `rules` are saved as a mapping per column, or a list of them for a
column's [rules over time](/epftoolbox2/model-pipeline/information-set/#rules-over-time); an `Availability` writes `vintage`,
`valid_from` and `valid_until` only when set.

```yaml
information_set:
  issue_time: "11:45"
  issue_timezone: Europe/Brussels
availability: raise
models:
- class: OLSModel
  params:
    predictors:
    - load_actual
    - is_monday_d+{horizon}
    - price_d-1
    - warsaw_temperature_2m_d+{horizon}
    training_window: 365
    name: OLS
    scaler: standard
- class: LassoCVModel
  params:
    predictors:
    - load_actual
    - is_monday_d+{horizon}
    - price_d-1
    - warsaw_temperature_2m_d+{horizon}
    training_window: 365
    cv: 5
    name: LassoCV
    scaler: standard
evaluators:
- class: MAEEvaluator
  params: {}
exporters:
- class: TerminalExporter
  params:
    show: [summary, horizon]
- class: ExcelExporter
  params:
    path: results.xlsx
```

## Serialization Rules

| Type | Behavior |
|------|----------|
| `str`, `int`, `float`, `bool`, `list`, `dict`, `None` | Serialized as-is |
| `Path` | Converted to `str` |
| numpy scalar / array | Converted to plain `int`/`float`/`list` |
| `tuple`, `range` (e.g. `hidden=(256, 128)`) | Converted to `list`; the model reloads with the list |
| Anything else (`set`, callable, arbitrary object) | **Raises `TypeError`** naming the model and the parameter. A model, evaluator or exporter parameter is never dropped silently |
| Callable predictors | **Raises `TypeError`** naming the model. Use `"{horizon}"` string templates instead |
| A module-level function of `ctx` as `predictors` | Saved as `{function: "package.module:name"}` and loaded by importing it. A lambda, nested function or bound method **raises `TypeError`** |
| Model `scaler` | Saved as a name (`standard`) or a `{name, params}` mapping. A scaler instance is converted when the model is built. A model without `scaler` loads with `standard` |
| Model `refit` | Saved as `refit: 7D` (a `"kD"` or `"kMS"` string) only when set. A model without it fits every forecast on its own, as every file saved before the setting did. See [Refitting on a calendar](/epftoolbox2/model-pipeline/time-and-calendars/#refitting-on-a-calendar) |
| `EconomicEvaluator` `strategy` | Saved inside the evaluator as `{class: BatteryArbitrage, params: {...}}` and rebuilt on load |
| Private attrs (`_name`) | Excluded |

## Callable Predictors

Callable predictors (a function of `horizon`, or of `horizon` and `hour`, as the whole list or inside it) cannot be
serialized to YAML yet (a [function of `ctx`](/epftoolbox2/model-pipeline/predictor-functions/#saving-to-yaml) can). `save()` raises a `TypeError` that names the model, and leaves an existing file untouched.
List the predictors explicitly instead, with `"{horizon}"` string templates:

```python
# Instead of:
lambda h: f"warsaw_temperature_2m_d+{h}"

# Use:
"warsaw_temperature_2m_d+{horizon}"
```

## Shared Predictor Lists

If the same predictor list object is passed to several models (as `predictors` is above), each model gets the full list
in the YAML. `save()` never writes YAML anchors and aliases (`&id001` / `*id001`) for `ModelPipeline`,
`DataPipeline` or `Workflow`, so a list can be edited in one model without touching the others. YAML you write
yourself may use anchors; they are read as usual, and a saved copy has the lists written out in full.

## Registering Custom Models/Evaluators/Exporters

Add to `COMPONENT_REGISTRY` in `model_pipeline.py`:

```python
COMPONENT_REGISTRY["models"]["MyModel"] = "mypackage.models.my_model"
COMPONENT_REGISTRY["evaluators"]["MyEvaluator"] = "mypackage.evaluators.my_evaluator"
COMPONENT_REGISTRY["exporters"]["MyExporter"] = "mypackage.exporters.my_exporter"
COMPONENT_REGISTRY["strategies"]["MyStrategy"] = "mypackage.strategies.my_strategy"  # for EconomicEvaluator
```
