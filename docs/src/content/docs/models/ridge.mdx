Ridge regression using scikit-learn's [`RidgeCV`](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.RidgeCV.html) with `cv=None`. On every fit it picks the penalty from a grid by **leave-one-out** cross-validation of the training rows, which `RidgeCV` computes in closed form without refitting, and fits the ridge with it. A model is one penalty search and one fit per forecast, or per refit unit with `refit=`.

## Basic Usage

```python
from epftoolbox2.models import RidgeModel

model = RidgeModel(
    predictors=[
        "load_actual",
        "is_monday_d+{horizon}",
        "is_tuesday_d+{horizon}",
        "is_wednesday_d+{horizon}",
        "is_thursday_d+{horizon}",
        "is_friday_d+{horizon}",
        "is_saturday_d+{horizon}",
        "is_sunday_d+{horizon}",
        "is_holiday_d+{horizon}",
        "daylight_hours_d+{horizon}",
    ],
    training_window=365,
    name="Ridge",
)
```

## Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `predictors` | List or function | Required | Predictor specifications (strings, `{horizon}` templates, or callables), or a [function of `ctx`](/epftoolbox2/model-pipeline/predictor-functions/) returning the list for each forecast |
| `training_window` | int | `365` | Days of training data |
| `alphas` | sequence of float or None | `None` | The penalties to choose from, positive and finite, in the order tried. `None` is `np.logspace(-3, 4, 36)`: 36 values from 0.001 to 10 000. See [The penalty](#the-penalty) |
| `name` | str | `"Model"` | Display name for reports |
| `scaler` | str, dict or scaler | `"standard"` | `"standard"`, `"asinh"` or `"npit"`, or `{"name": ..., "params": {...}}`. See [Scalers and VSTs](/epftoolbox2/models/scalers/) |
| `newest_target` | str | `"d-1"` | The newest target a forecast issued on D trains on: `"d-1"`, or `"published"`, every target its rule says is known by the issue time, which needs an information set. See [The newest target](/epftoolbox2/model-pipeline/time-and-calendars/#the-newest-target) |
| `refit` | str or None | `None` | How often the model is fitted: `None` fits every forecast on its own, `"kD"` once every k days and `"kMS"` on the first of every k-th month (k a whole number from 1), on a fixed calendar, such as `"7D"` (Mondays) or `"1MS"`. See [Refitting on a calendar](/epftoolbox2/model-pipeline/time-and-calendars/#refitting-on-a-calendar) |
| `fit_intercept` | bool | `True` | Keyword-only. scikit-learn's: fit an intercept on the standardised data, which the penalty doesn't shrink. `False` fits none |

Callable predictors accept `(horizon)` or `(horizon, hour)`. See [OLSModel](/epftoolbox2/models/ols/#parameters) for details.

## The penalty

The columns and the target are standardised on the training rows before the fit (the [scaler](/epftoolbox2/models/scalers/); binary 0/1 columns stay as they are), so one penalty shrinks every column alike. A penalty near 0.001 is close to ordinary least squares, and a very large one shrinks every coefficient towards 0, to a forecast near the training mean (the intercept isn't shrunk).

- **Leave-one-out, not K-fold.** The error of a penalty is the mean squared error of predicting each training row from a ridge fitted on all the others. The first penalty of the grid with the lowest error wins, so the order of a grid you set matters only for an exact tie. The training rows are consecutive days, which are not independent draws: the leave-one-out error ranks the penalties and is not an estimate of the forecast error.
- **The grid is recorded.** A run's manifest holds the grid in full, also when `alphas=None`, so results made with another grid are refused on resume. A saved pipeline writes `alphas` only when you set it.
- **At least 3 training rows.** With one or two rows every leave-one-out error is undefined, so such a forecast is skipped and counted as `fit_error` instead of being made with an arbitrary penalty.
- **Not below 1e-6.** scikit-learn's leave-one-out route loses digits in proportion to 1/penalty: in the cases measured, the standardised coefficients differ from a plain `Ridge`'s by about 5e-11 at 0.001 and 4e-6 at 1e-9. The default grid starts at 0.001.
- **Coefficients** are `coef_` in the standardised space, as for the other models. The penalty each forecast chose isn't in the records.

## When to Use

- **Many correlated predictors**: Ridge shrinks them together instead of dropping some, which Lasso does
- **More columns than rows in a short window**: the penalty keeps the fit defined where OLS has many solutions
- **A fit you can reproduce**: a closed form with no iteration or random start, so on one installation the same data and grid give the same numbers to the bit, however many processes run it

## Example

```python
from epftoolbox2.pipelines import ModelPipeline
from epftoolbox2.models import OLSModel, RidgeModel
from epftoolbox2.evaluators import MAEEvaluator
from epftoolbox2.exporters import TerminalExporter

predictors = [
    "load_actual",
    "is_monday_d+{horizon}",
    "is_tuesday_d+{horizon}",
    "is_wednesday_d+{horizon}",
    "is_thursday_d+{horizon}",
    "is_friday_d+{horizon}",
    "is_saturday_d+{horizon}",
    "is_sunday_d+{horizon}",
    "is_holiday_d+{horizon}",
    "daylight_hours_d+{horizon}",
    *[f"load_actual_h-{i}" for i in range(1, 169)],
]

pipeline = (
    ModelPipeline()
    .add_model(OLSModel(predictors=predictors, name="OLS"))
    .add_model(RidgeModel(predictors=predictors, name="Ridge"))
    .add_model(RidgeModel(predictors=predictors, alphas=[1, 10, 100, 1000], name="Ridge_coarse"))
    .add_evaluator(MAEEvaluator())
    .add_exporter(TerminalExporter())
)

report = pipeline.run(data=df, test_start="2024-02-01", test_end="2024-03-01")
```

In a YAML pipeline the grid is written only when set:

```yaml
models:
  - class: RidgeModel
    params:
      predictors: [load_actual, "is_monday_d+{horizon}"]
      training_window: 365
      alphas: [1.0, 10.0, 100.0, 1000.0]
      name: Ridge_coarse
```

<Aside>
  Ridge never sets a coefficient to exactly zero. To select columns use [LassoCVModel](/epftoolbox2/models/lasso/).
</Aside>
