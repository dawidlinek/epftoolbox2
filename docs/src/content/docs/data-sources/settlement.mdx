# SettlementPriceSource

Loads daily settlement or close prices, such as TTF gas, EUA carbon, API2 coal and Brent, from **your own** CSV or Parquet files. Each row gets the close that was known at the issue time of its day.

<Aside type="caution">
  This source ships no data and downloads nothing. Exchange settlement prices (EEX, ICE and others) are licensed, and their terms forbid systematic redistribution. Keep the files outside the repository and don't commit them or caches built from them.
</Aside>

## Basic Usage

```python
import pandas as pd
from epftoolbox2.data.sources import SettlementPriceSource

source = SettlementPriceSource(
    file_path="~/data/fuels.csv",
    columns={"TTF_settle": "ttf", "EUA_settle": "eua", "API2_settle": "coal", "Brent_settle": "brent"},
    timezone="Europe/Warsaw",         # forecast day D; same zone as TimezoneTransformer
    issue_time="11:30",               # forecasts are issued at 11:30 on D
    close_time="19:30",               # from when a day's settlement price is known
    close_timezone="Europe/London",
    trading_calendar="IFEU",          # ICE Futures Europe holidays
)

df = source.fetch(
    start=pd.Timestamp("2024-01-01", tz="UTC"),
    end=pd.Timestamp("2024-06-01", tz="UTC"),
)
# ttf_d-1, eua_d-1, coal_d-1, brent_d-1 on every hourly row
```

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `file_path` | str \| List[str] | Yes | - | CSV (`.csv`) or Parquet (`.parquet`, `.pq`) file, or several files merged on the date column |
| `columns` | List[str] \| Dict[str, str] | Yes | - | Price columns: a list keeps the names, a dict renames `{file column: output name}` |
| `timezone` | str | Yes | - | Time zone of the forecast day D and of `issue_time`. Must match `TimezoneTransformer(target_tz=...)` |
| `issue_time` | str | No | `"11:30"` | Local time `"HH:MM"` at which forecasts are issued on D |
| `close_time` | str | No | `"23:59"` | Time `"HH:MM"` on the trading day from which its close counts as known (settlement publication time) |
| `close_timezone` | str \| None | No | `None` | Time zone of `close_time`; `None` = `timezone` |
| `date_column` | str | No | `"date"` | Column with the trading date |
| `date_format` | str \| None | No | `None` | strftime format of the dates, e.g. `"%d.%m.%Y"`; `None` lets pandas infer (safe for ISO dates) |
| `trading_calendar` | str | No | `"weekdays"` | `"weekdays"`, a `holidays` financial market code, or `"file"` (see below) |
| `lags` | int \| List[int] | No | `1` | Day offset(s) `k >= 0`; column `x_d-k` holds the prevailing close on D-k |
| `freq` | str | No | `"1h"` | Row frequency of the output; every row of a day gets that day's value |
| `separator` | str | No | `","` | CSV separator |

## File format

One row per trading date, one column per price (values below are illustrative); files may hold different columns and are merged on the date:

```csv
date,TTF_settle,EUA_settle,API2_settle,Brent_settle
2024-03-27,27.83,60.12,114.50,86.09
2024-03-28,27.54,61.05,113.75,87.48
2024-04-02,26.10,61.90,112.00,88.92
```

Non-numeric cells are ignored with a warning. Two different values for the same date and column raise an error.

## What each row gets

For a series `x`, the **prevailing close on calendar day T** is the close of the last trading day on or before T. It is forward-filled over weekends and holidays, and nothing else.

On every row of local day D, the column `x_d-k` holds the prevailing close on D-k. It is kept only if that close was known by `issue_time` on D, i.e. if its trading day at `close_time` (in `close_timezone`) is not later than D at `issue_time` (in `timezone`). Otherwise the value is `NaN` and a warning is logged.

With the default `lags=1`:

| Row day D | `x_d-1` |
|-----------|---------|
| Tuesday | Monday's close |
| Saturday, Sunday, Monday | Friday's close |
| Saturday to Monday after Good Friday (a holiday in `"IFEU"`) | Thursday's close |

This is the last close available before the issue time on D whenever the close comes after the issue time of the same day, which is the usual case. `x_d-2`, `x_d-7` etc. give older prevailing closes.

### Why D-1 and not D

Row D is the issue day: `ModelPipeline` forecasts D+1 and later from it. A close on D is set in the afternoon or evening of D, after the day-ahead auction closes at 12:00 CET. Using it would be look-ahead, and it partly reflects the auction result you are trying to forecast. D-1's close is the T-2 close relative to the first delivery day T = D+1. Marcjasz, Narajewski, Weron & Ziel (2023, *Energy Economics* 125) use exactly these T-2 fuel closes, because only information available around 11:30 CET on T-1 may be used, and they list the recent gas price among the most important inputs.

<Aside type="danger">
  Don't use same-day closes. `lags=0` is only meaningful when a price is known before `issue_time` on the same day (e.g. a morning auction with `close_time` set accordingly). With the default `close_time="23:59"`, a same-day close is never used: `lags=0` is then `NaN` on every trading day and filled only on weekends and holidays.
</Aside>

<Aside type="caution">
  Set `close_time` to when the settlement price is actually **published** in your data, not to the end of trading, if these differ. The default `"23:59"` in the forecast time zone is conservative. A `close_time` that is too early leaks same-day information once `issue_time` is later than it.
</Aside>

### Trading calendars and missing closes

`trading_calendar` decides which days are expected to have a close:

| Value | Trading days |
|-------|--------------|
| `"weekdays"` | Monday to Friday |
| a `holidays` financial market code, e.g. `"IFEU"` (ICE Futures Europe), `"ECB"`/`"TAR"` (TARGET2), `"NYSE"` | Weekdays without that market's holidays |
| `"file"` | Exactly the dates present in the file |

Any date that has a close is also a trading day. A trading day **without** a close is a gap: rows that need it are `NaN`, not filled from an earlier day, and a warning lists the missing dates. The same applies after the end of the file, so an outdated file can't silently repeat its last price. With `"weekdays"`, exchange holidays show up as gaps; pick the market calendar, or `"file"` if your file already contains exactly the trading days.

<Aside type="caution">
  `ModelPipeline` skips a forecast whose predictors contain `NaN`, so gaps drop forecasts. Check how many forecasts each model produced.
</Aside>

## Parquet

Parquet files need a Parquet engine, which epftoolbox2 doesn't install: `pip install pyarrow`.

## Caching

`get_cache_config()` returns `None`: the files are read on every run, so edits to them take effect immediately.
