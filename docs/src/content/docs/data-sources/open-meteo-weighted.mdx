# OpenMeteoWeightedSource

Fetches the same weather variables at several locations with [`OpenMeteoSource`](/data-sources/openmeteo/) or [`OpenMeteoSingleRunsSource`](/data-sources/open-meteo-single-runs/) and combines them into one weighted series per variable — for example a population-weighted temperature or a capacity-weighted wind speed for a whole bidding zone, instead of a single city's forecast.

<Aside type="caution" title="Weights must be known on D">
  Weights are fixed constructor parameters and apply to the whole sample. Use population or installed-capacity figures from a reference date **before the sample starts** (e.g. the start of the backtest, or the census/registry date closest to it before that). Using end-of-sample figures for the whole history is look-ahead: the model would see population or capacity growth that had not happened yet on earlier forecast days.
</Aside>

## Basic Usage

```python
from epftoolbox2.data.sources import OpenMeteoWeightedSource

source = OpenMeteoWeightedSource(
    locations=[
        {"name": "warsaw", "latitude": 52.2297, "longitude": 21.0122, "weight": 1.86},   # millions
        {"name": "krakow", "latitude": 50.0647, "longitude": 19.9450, "weight": 0.80},
        {"name": "gdansk", "latitude": 54.3520, "longitude": 18.6466, "weight": 0.47},
    ],
    source_params={"model": "icon_seamless", "horizon": 5, "columns": ["temperature_2m", "wind_speed_10m"]},
    prefix="pl",
)

df = source.fetch(start="2024-01-01", end="2024-06-01")
```

`locations` can also be the compact string `"warsaw:52.2297:21.0122:1.86, krakow:50.0647:19.9450:0.80"` — handy for YAML or the TUI.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `locations` | List[dict] \| str | Yes | - | `[{"name", "latitude", "longitude", "weight"}, ...]` or the compact string form. Names must use letters, digits and underscores, and be unique; weights must be positive numbers. |
| `source` | str | No | `"OpenMeteoSource"` | `"OpenMeteoSource"` (Previous Runs API) or `"OpenMeteoSingleRunsSource"` (Single Runs API) |
| `source_params` | dict \| None | No | `None` | Parameters for the underlying source, shared by every location — anything but `latitude`, `longitude` and `prefix`, which come from `locations` |
| `prefix` | str | No | `""` | Prefix for the weighted columns |
| `keep_locations` | bool | No | `False` | Also return each location's own columns as `{prefix}_{name}_{variable}_d+{i}` |

## How the average is computed

Every location is fetched with the **same** underlying source and `source_params`, so all locations share one vintage rule (issue time, publication delay, run selection). For each output column `{prefix}_{variable}_d+{i}`:

- weights are normalised to sum to 1 across the given locations;
- most variables use a plain weighted mean, `sum(w_l * x_l) / sum(w_l)`;
- variables whose name contains `direction` (e.g. `wind_direction_10m`) use a **weighted circular mean**, so 350° and 10° average to about 0°, not 180°;
- `weather_code` is categorical and is **never averaged** — it is dropped from the combined output; set `keep_locations=True` to keep it per location instead.

A row is missing (`NaN`) if **any** location is missing at that row: weights are never re-normalised over just the available locations, so a location dropping out never silently shifts the weighting. Locations are unioned on their index first (a location's own missing timestamps count as missing there too), and trailing rows with no value at all are dropped, as in the other Open-Meteo sources.

## Choosing an underlying source

`source="OpenMeteoSource"` (default) uses the Previous Runs API — see its own page for the vintage rule and horizon limit, which apply identically to every location here. `source="OpenMeteoSingleRunsSource"` uses the Single Runs API instead — same run-selection rule, and the same shorter archive for most models.

## Output Column Naming

Weighted columns: `{prefix}_{variable}_d+{i}`. With `keep_locations=True`, per-location columns are also returned as `{prefix}_{name}_{variable}_d+{i}` (including `weather_code`, which has no weighted equivalent).

```python
# Example output columns (keep_locations=True):
# pl_temperature_2m_d+1
# pl_warsaw_temperature_2m_d+1
# pl_krakow_temperature_2m_d+1
# pl_gdansk_temperature_2m_d+1
```

## Caching

The cache key includes `locations` (name, latitude, longitude and weight of every location), `source`, the underlying source's own cache config (minus `latitude`, `longitude` and `prefix`, which vary per location), `prefix`, `keep_locations` and a `schema_version`.
