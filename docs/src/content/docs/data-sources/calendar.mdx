# CalendarSource

Generates calendar features: holidays, weekday, hour of day (or period of day), month, and sunrise/sunset.
Every feature is computed from the **local date and wall-clock time** in the country's time zone, while the index
stays in UTC like every other source. All features are known in advance, so their `_d+k` versions are legal
predictors.

<Aside>
  CalendarSource uses the [holidays](https://pypi.org/project/holidays/) Python package for holiday detection. See their documentation for the [complete list of supported countries](https://python-holidays.readthedocs.io/en/latest/index.html#available-countries), subdivisions and categories.
</Aside>

## Basic Usage

```python
import pandas as pd
from epftoolbox2.data.sources import CalendarSource

source = CalendarSource(
    country="PL",
    holidays="binary",
    weekday="number",
    hour="number",
)

df = source.fetch(
    start=pd.Timestamp("2024-01-01", tz="UTC"),
    end=pd.Timestamp("2025-01-01", tz="UTC"),
)
```

`fetch(start, end)` returns the rows of the `freq` grid in **[start, end)**, with a UTC index. A local day
has 23, 24 or 25 hourly rows (92, 96 or 100 at 15 minutes) depending on DST.

## Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `country` | str | Required | Country code (see the list below) |
| `timezone` | str \| None | `None` | Time zone whose local dates and times define the features. `None` inherits `DataPipeline.timezone` when part of a pipeline; standalone, it falls back to the country's own zone |
| `holidays` | str/bool | `"binary"` | Holiday output format |
| `weekday` | str/bool | `"number"` | Weekday output format |
| `hour` | str/bool | `False` | Hour (or period) output format |
| `month` | str/bool | `False` | Month output format |
| `daylight` | bool | `False` | Add `sunrise`, `sunset` (local decimal hours) and `daylight_hours` |
| `lat` | float | Auto | Latitude for daylight (default: the country's capital) |
| `lon` | float | Auto | Longitude for daylight (default: the country's capital) |
| `prefix` | str | `""` | Column name prefix, used as is (`"cal_"` gives `cal_is_holiday`) |
| `freq` | str | `"1h"` | Row spacing: a divisor of one hour (`"15min"`, `"30min"`) or whole hours dividing a day |
| `subdiv` | str | `None` | Subdivision for regional holidays: `"BY"` or `"DE-BY"` (Bavaria), `"ENG"` (England), `"ZH"` (Zurich) |
| `categories` | str/List[str] | `None` | Holiday categories of the `holidays` package, e.g. `["public", "bank"]`; `None` means public holidays only |
| `bridge_days` | bool | `False` | Add `is_bridge_day` (see [Additional features](#additional-features)) |
| `christmas_period` | bool | `False` | Add `is_christmas_period` (24 December to 1 January) |
| `holiday_distance` | int | `0` | If N > 0, add `days_to_holiday` and `days_since_holiday`, capped at N |
| `dst_switch` | bool | `False` | Add `is_dst_switch_day` (local days with 23 or 25 hours) |
| `regimes` | bool/dict | `False` | Market-regime step dummies `regime_{name}`: `True` for the default set, or `{name: "YYYY-MM-DD"}` |
| `school_holidays` | bool | `False` | Download school holiday flags from the [OpenHolidays API](https://www.openholidaysapi.org) (see [School holidays](#school-holidays) below) |
| `school_subdivisions` | str/List[str] | `None` | OpenHolidays subdivision codes, e.g. `["PL-MZ", "PL-SL"]` or `"MZ,SL"` (the country prefix is optional). `None`: only holidays that apply to the whole country |
| `school_weights` | dict/List[float] | `None` | Weight per subdivision for `school_holiday_share`: `{code: weight}`, or numbers in the order of `school_subdivisions`. With a dict, `school_subdivisions` defaults to its keys |

<Aside type="tip">
  Inside a `DataPipeline`, leave `timezone` unset: it inherits `DataPipeline.timezone`, the single place the
  market zone needs to be written (an explicit, different zone still raises). Standalone, it falls back to the
  zone the country code implies.
</Aside>

## Output Formats

### Holidays

| Value | Columns | Example |
|-------|---------|---------|
| `False` | None | - |
| `"binary"` | `is_holiday` | 0 or 1 |
| `"name"` | `holiday_name` | "Christmas Day" or None (two holidays on one day are joined with `"; "`) |
| `"onehot"` | `is_holiday`, `holiday_{name}` | One 0/1 column per holiday, e.g. `holiday_new_years_day` |

- **Names are in English** (`en_US`) for every country. Without a pinned language the `holidays` package
  follows the process locale, so the same config gave different column names on machines with different
  `LANG` settings.
- One-hot names are lower case ASCII with underscores. The columns cover every holiday of the years touched
  by `[start, end)`, so the column set does not depend on which holidays fall inside the range.
- Only **public** holidays are flagged by default, and only national ones. Use `subdiv` for regional holidays
  (Germany flags 9 days in 2024, Bavaria 12; England adds Easter Monday and the Late Summer Bank Holiday) and
  `categories` for other kinds, e.g. Swedish Midsummer Eve and Christmas Eve are in the `"bank"` category
  (which also has afternoon-only days such as "Maundy Thursday (from 2pm)"; they are flagged for the whole
  day). `categories` replaces the default, so include `"public"` when you want both.
- Sweden: the `holidays` package lists every Sunday as a Swedish holiday; CalendarSource excludes them.

<Aside type="caution">
  `"name"` outputs (`holiday_name`, `weekday_name`, `month_name`) are strings, for inspection only. Models
  convert every column of the frame to numbers, so drop these columns before modelling.
</Aside>

### Weekday

| Value | Columns | Example |
|-------|---------|---------|
| `False` | None | - |
| `"number"` | `weekday` | 0 (Monday) to 6 (Sunday) |
| `"name"` | `weekday_name` | "monday", "tuesday", ... |
| `"onehot"` | `is_monday`, `is_tuesday`, ... | 7 columns |

### Hour

The column depends on `freq`:

| `freq` | Value | Columns | Example |
|--------|-------|---------|---------|
| hourly or coarser | `"number"` | `hour` | 0 to 23 (local hour of day) |
| hourly or coarser | `"onehot"` | `is_0`, `is_1`, ..., `is_23` | 24 columns |
| sub-hourly | `"number"` | `period` | 0 to 95 at `"15min"`, 0 to 47 at `"30min"` |
| sub-hourly | `"onehot"` | `is_period_0`, ..., `is_period_95` | one column per period of the day |

`period` is the index of the period within the local day on the wall-clock grid (`hour * 4 + minute // 15` at
15 minutes), the same numbering the models use for their `hour` key. On the fall-back day the repeated hour's
periods occur twice; on the spring-forward day the missing hour's periods are absent.

<Aside type="note">
  The models fit one model per period of the day and drop any data column named `hour`, so these columns are
  mainly useful outside `epftoolbox2` models.
</Aside>

### Month

| Value | Columns | Example |
|-------|---------|---------|
| `False` | None | - |
| `"number"` | `month` | 1 to 12 |
| `"name"` | `month_name` | "january", "february", ... |
| `"onehot"` | `is_january`, `is_february`, ... | 12 columns |

### Daylight

With `daylight=True`, `sunrise` and `sunset` are local decimal hours (06:30 is 6.5) and `daylight_hours` is
their difference, computed with [astral](https://pypi.org/project/astral/) for `lat`/`lon`. On polar days or
nights (only possible with a far-northern `lat`) the three columns are NaN and a warning is logged.

## Additional features

These are off by default. All of them are known in advance, so their `x_d+k` versions (from
`LagTransformer(lags=[-k])`) are legal predictors. Bridge days and holiday distances use the same holiday
calendar as `holidays` (country, `subdiv`, `categories`), even when `holidays=False`, and look beyond
`[start, end)` where needed, so values at the edges of the range are correct.

<Aside type="caution">
  `LagTransformer` currently shifts by elapsed time, not calendar days, so on a local-time index a `_d+1`
  calendar column points to the wrong day at one row around each DST switch (a known issue).
</Aside>

| Parameter | Columns | Definition |
|-----------|---------|------------|
| `bridge_days=True` | `is_bridge_day` | A working day (Monday to Friday, not a holiday) whose previous and next days are both a weekend day or a holiday: the Friday after a Thursday holiday, the Monday before a Tuesday holiday, or a day between two holidays (2 May in Poland in 2024) |
| `christmas_period=True` | `is_christmas_period` | Local dates from 24 December to 1 January inclusive |
| `holiday_distance=N` | `days_to_holiday`, `days_since_holiday` | Days to the next and since the previous holiday, 0 on a holiday, capped at N (so N means "N or more") |
| `dst_switch=True` | `is_dst_switch_day` | 1 on every row of a local day with 23 or 25 hours |
| `regimes=...` | `regime_{name}` | 0 before the regime's first local delivery day, 1 from it on |

### Regime dummies

`regimes=True` adds the changes below that apply to `country`. The date is the first **delivery** day; the
first auction was the day before.

| Name | Date | Countries | Change |
|------|------|-----------|--------|
| `de_at_split` | 2018-10-01 | DE, AT | Split of the German-Austrian bidding zone |
| `brexit_decoupling` | 2021-01-01 | GB, IE | GB and the Irish SEM leave implicit day-ahead coupling with SDAC |
| `core_fb` | 2022-06-09 | AT, BE, CZ, DE, FR, HU, NL, PL, RO, SK | Core flow-based market coupling |
| `nordic_fb` | 2024-10-30 | DK, FI, NO, SE | Nordic flow-based market coupling |
| `sdac_15min_mtu` | 2025-10-01 | AT, BE, BG, CZ, DE, DK, ES, FI, FR, GR, HU, IT, NL, NO, PL, PT, RO, SE, SK | 15-minute market time unit in SDAC |
| `sem_30min_mtu` | 2025-10-01 | IE | 30-minute market time unit in the SEM day-ahead market |

The set is available as `epftoolbox2.data.sources.calendar.DEFAULT_REGIMES`. A dict replaces it, so list the
defaults you want to keep:

```python
source = CalendarSource(
    country="PL",
    regimes={"core_fb": "2022-06-09", "sdac_15min_mtu": "2025-10-01", "my_change": "2024-07-01"},
)
# Columns: is_holiday, weekday, regime_core_fb, regime_sdac_15min_mtu, regime_my_change
```

<Aside type="note">
  A regime dummy only helps once the training window spans the change. While the window lies entirely before
  it, the column is all zeros and gets no weight, so the first forecasts after the change are made as if nothing
  had happened. Don't pool data before and after 2025-10-01 without a regime flag or a separate model.
</Aside>

## School holidays

With `school_holidays=True`, CalendarSource additionally downloads school holidays from the
[OpenHolidays API](https://www.openholidaysapi.org) and turns them into flags on the same local-date grid as
every other feature. With several `school_subdivisions` and `school_weights` (e.g. population) it also gives the
weighted share of the population on school holidays. **No API key required.** This is the only case where
CalendarSource makes network calls; without it, it stays offline and deterministic.

<Aside type="caution" title="Licence and attribution">
  The data is published under the [Open Database License (ODbL 1.0)](https://opendatacommons.org/licenses/odbl/1-0/).
  Credit it when you publish results or share a dataset built from it, e.g. *"School holidays: OpenHolidays API
  (www.openholidaysapi.org), ODbL 1.0"* (also available as `epftoolbox2.data.sources._openholidays.ATTRIBUTION`).
  If you publicly share a database derived from it, the ODbL share-alike terms apply to it.
</Aside>

```python
# One region: a single flag
source = CalendarSource(country="PL", school_holidays=True, school_subdivisions="PL-MZ")

# Several regions weighted by population (millions): one flag per region plus the weighted share
source = CalendarSource(
    country="PL",
    school_holidays=True,
    school_weights={"PL-MZ": 5.5, "PL-SL": 4.4, "PL-WP": 3.5},
)
```

Subdivision codes are listed by the API, e.g. `https://openholidaysapi.org/Subdivisions?countryIsoCode=PL`
(Poland uses `PL-DS`, `PL-KP`, ..., `PL-ZP`; Germany `DE-BW`, `DE-BY`, ...). An unknown code raises an error.

### Output

| Configuration | Columns |
|---------------|---------|
| no or one `school_subdivisions` entry | `is_school_holiday` |
| several `school_subdivisions` entries | `is_school_holiday_{code}`, e.g. `is_school_holiday_pl_mz` |
| with `school_weights` | also `school_holiday_share` = Σ weight × flag / Σ weight |

Values are `1.0` on a school holiday and `0.0` otherwise (weekends outside holidays are `0.0`); CalendarSource's
`prefix` applies to these columns like to every other feature.

- A holiday of a subdivision also counts for its children (a `DE-BY` holiday applies to `DE-BY-AU`), not the other way round.
- In subdivisions whose holidays differ by school type (e.g. general and vocational schools in `DE-MV`), a day is flagged when any group is on holiday.
- Entries marked as half days are ignored.
- Without `school_subdivisions`, only holidays marked as country-wide count. In Poland that is the spring, summer
  and Christmas breaks but not the regional winter breaks; Germany has no country-wide school holidays at all.

### Missing data is NaN, not 0

The API only knows school years that have been entered, so a `0` would be ambiguous. Every school year has
holidays, so a stretch of more than a year without any is treated as missing: those dates are **NaN** (and the
share is NaN too), and a warning names them. The source queries 400 days beyond both ends of the range to decide
this. It happens before the data's history starts and for school years that aren't published yet.

History start by country (from the [OpenHolidays data repository](https://github.com/openpotato/openholidaysapi.data)):

| From | Countries |
|------|-----------|
| 2012 | DE |
| 2015 | HU, RO |
| 2017 | AT |
| 2018 | FR |
| 2020 | BE, BG, CH, CZ, ES, IE, IT, NL, PL, PT, SK |
| no school holidays | SE (public holidays only); DK, FI, GB, GR and NO are not covered |

For Poland the first recorded school holiday is the 2019/20 Christmas break (from 23 December 2019), so earlier
dates are NaN.

<Aside type="caution">
  Models drop forecasts whose predictors are NaN, so a range reaching before the history start silently loses
  forecasts. Start the range after it, or leave the column out for earlier periods.
</Aside>

### Look-ahead

School holiday calendars are set by regulation months or years ahead, so the flags and their `_d+k` versions
are legal predictors. Two caveats:

- The API serves today's version of each calendar. A change decided at short notice (an extra day off) appears
  as if it had been known in advance, and gaps in the data (e.g. a break not yet entered) are not detected when
  shorter than a year.
- Use weights known at the start of your sample (e.g. the census before it), not end-of-sample figures.

### Caching

Not cached: a run with `school_holidays=True` makes one request for the subdivisions plus one per 1,000 days,
and a cache would keep the NaN of school years published after it was written. The API's data can be corrected
over time, so keep the pipeline output (e.g. `DataPipeline.run(..., cache="data.csv")`) if you need to reproduce
a run exactly.

## Example: Full Features

```python
source = CalendarSource(
    country="DE",
    subdiv="BY",
    holidays="binary",
    weekday="number",
    hour="number",
    month="number",
    bridge_days=True,
    regimes=True,
)

# Output columns: is_holiday, weekday, hour, month, is_bridge_day,
# regime_de_at_split, regime_core_fb, regime_sdac_15min_mtu
```
