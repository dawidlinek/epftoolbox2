# SchoolHolidaysSource

Downloads school holidays from the [OpenHolidays API](https://www.openholidaysapi.org) and turns them into
flags on a UTC grid built from **local dates**, like `CalendarSource`. With several subdivisions and weights
(e.g. population) it also gives the weighted share of the population on school holidays. **No API key
required.**

## Basic Usage

```python
import pandas as pd
from epftoolbox2.data.sources import SchoolHolidaysSource

# One region: a single flag
source = SchoolHolidaysSource(country="PL", subdivisions="PL-MZ")

# Several regions weighted by population (millions): one flag per region plus the weighted share
source = SchoolHolidaysSource(
    country="PL",
    weights={"PL-MZ": 5.5, "PL-SL": 4.4, "PL-WP": 3.5},
)

df = source.fetch(
    start=pd.Timestamp("2023-01-01", tz="UTC"),
    end=pd.Timestamp("2025-01-01", tz="UTC"),
)
```

`fetch(start, end)` returns the rows of the `freq` grid in **[start, end)** with a UTC index; every row carries
the value of its local date.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `country` | str | Yes | - | ISO 3166-1 country code, e.g. `"PL"` |
| `subdivisions` | str/List[str] | No | `None` | OpenHolidays subdivision codes, e.g. `["PL-MZ", "PL-SL"]` or `"MZ,SL"` (the country prefix is optional). `None`: only holidays that apply to the whole country |
| `weights` | dict/List[float] | No | `None` | Weight per subdivision for `school_holiday_share`: `{code: weight}`, or numbers in the order of `subdivisions`. With a dict, `subdivisions` defaults to its keys |
| `timezone` | str | No | Auto | Time zone whose local dates define the flags (default: the country's, as in `CalendarSource`; required for other countries) |
| `prefix` | str | No | `""` | Column name prefix, used as is |
| `freq` | str | No | `"1h"` | Row spacing, as in `CalendarSource` |

Subdivision codes are listed by the API, e.g. `https://openholidaysapi.org/Subdivisions?countryIsoCode=PL`
(Poland uses `PL-DS`, `PL-KP`, ..., `PL-ZP`; Germany `DE-BW`, `DE-BY`, ...). An unknown code raises an error.

## Output

| Configuration | Columns |
|---------------|---------|
| no or one subdivision | `is_school_holiday` |
| several subdivisions | `is_school_holiday_{code}`, e.g. `is_school_holiday_pl_mz` |
| with `weights` | also `school_holiday_share` = Σ weight × flag / Σ weight |

Values are `1.0` on a school holiday and `0.0` otherwise (weekends outside holidays are `0.0`).

- A holiday of a subdivision also counts for its children (a `DE-BY` holiday applies to `DE-BY-AU`), not the other way round.
- In subdivisions whose holidays differ by school type (e.g. general and vocational schools in `DE-MV`), a day is flagged when any group is on holiday.
- Entries marked as half days are ignored.
- Without `subdivisions`, only holidays marked as country-wide count. In Poland that is the spring, summer and
  Christmas breaks but not the regional winter breaks; Germany has no country-wide school holidays at all.

## Missing data is NaN, not 0

The API only knows school years that have been entered, so a `0` would be ambiguous. Every school year has
holidays, so a stretch of more than a year without any is treated as missing: those dates are **NaN** (and the
share is NaN too), and a warning names them. The source queries 400 days beyond both ends of the range to decide
this. It happens before the data's history starts and for school years that aren't published yet.

History start by country (from the [OpenHolidays data repository](https://github.com/openpotato/openholidaysapi.data)):

| From | Countries |
|------|-----------|
| 2012 | DE |
| 2015 | HU, RO |
| 2017 | AT |
| 2018 | FR |
| 2020 | BE, BG, CH, CZ, ES, IE, IT, NL, PL, PT, SK |
| no school holidays | SE (public holidays only); DK, FI, GB, GR and NO are not covered |

For Poland the first recorded school holiday is the 2019/20 Christmas break (from 23 December 2019), so earlier
dates are NaN.

<Aside type="caution">
  Models drop forecasts whose predictors are NaN, so a range reaching before the history start silently loses
  forecasts. Start the range after it, or leave the column out for earlier periods.
</Aside>

## Look-ahead

School holiday calendars are set by regulation months or years ahead, so the flags and their `_d+k` versions
are legal predictors. Two caveats:

- The API serves today's version of each calendar. A change decided at short notice (an extra day off) appears
  as if it had been known in advance, and gaps in the data (e.g. a break not yet entered) are not detected when
  shorter than a year.
- Use weights known at the start of your sample (e.g. the census before it), not end-of-sample figures.

## Caching

Not cached: a run makes one request for the subdivisions plus one per 1,000 days, and a cache would keep the NaN
of school years published after it was written. The API's data can be corrected over time, so keep the pipeline
output (e.g. `DataPipeline.run(..., cache="data.csv")`) if you need to reproduce a run exactly.
