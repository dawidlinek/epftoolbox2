Loads tables of the Polish transmission system operator's reports API (`https://api.raporty.pse.pl`): the national load and PSE's day-ahead forecast of it, demand with wind and PV generation, the SDAC price of the Polish bidding zone in PLN, the prosumer net-billing price, cross-border flows and PSE's recommended-usage periods. **No API key.** Source: PSE.

<Aside type="caution">
  The API's terms of use are not published. Don't redistribute the data in bulk and don't commit it to a repository: the library's tests use synthetic answers, not PSE data.
</Aside>

## Basic Usage

```python
from epftoolbox2.pipelines import DataPipeline
from epftoolbox2.data.sources import PseSource
from epftoolbox2.data.transformers import TimezoneTransformer, ResampleTransformer, LagTransformer

pipeline = (
    DataPipeline()
    .add_source(PseSource(datasets=["kse-load", "csdac-pln"]))
    .add_transformer(TimezoneTransformer(target_tz="Europe/Warsaw"))
    .add_transformer(ResampleTransformer(freq="1h"))
    .add_transformer(LagTransformer(columns=["csdac_pln", "load_actual"], lags=[1, 2, 7], freq="day"))
    .add_transformer(LagTransformer(columns=["load_fcst"], lags=[-1], freq="day"))
)
df = pipeline.run("2025-01-01", "2025-03-01")
# csdac_pln, load_actual, load_fcst, csdac_pln_d-1, ..., load_actual_d-2, ..., load_fcst_d+1
```

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `datasets` | list[str] \| None | No | `["kse-load", "csdac-pln"]` | Datasets to load, from the table below |
| `columns` | list[str] \| None | No | `None` | Columns to keep. `None` = every column of the datasets, for `his-wlk-cal` `demand`, `wi`, `pv` and `jg`. A column of a dataset that is not in `datasets` raises |
| `prefix` | str | No | `""` | Column prefix, `{prefix}_{column}` |

`output_columns()` lists the names `fetch` returns. The output follows the dataset order of `datasets`, and within a dataset the order of the table.

## Datasets and columns

| Dataset | Columns | Meaning |
|---------|---------|---------|
| `kse-load` | `load_actual`, `load_fcst` | National load (MW) and PSE's day-ahead forecast of it |
| `his-wlk-cal` | `demand`, `wi`, `pv`, `jg` | Demand, wind, PV and generation (MW; `jg` is PSE's generation field). With `columns` also `jga`, `jgm`, `jgo`, `jgm1`, `jgm2`, `jgw1`, `jgw2`, `jgz1`, `jgz2`, `jgz3`, `jnwrb`, `swm_p`, `swm_np`, under PSE's field names |
| `csdac-pln` | `csdac_pln` | SDAC price of the Polish bidding zone in PLN/MWh: the EUR price times the day's EUR/PLN rate |
| `rce-pln` | `rce_pln` | Market energy price (RCE) of the prosumer net-billing scheme, PLN/MWh |
| `pdgsz` | `usage_fcst` | PSE's recommended-usage code of each hour. Hourly; see below |
| `przeplywy-mocy` | `flow_de_pl`, `flow_pl_de`, `flow_cz_pl`, `flow_pl_cz`, `flow_sk_pl`, `flow_pl_sk`, `flow_ua_pl`, `flow_pl_ua`, `flow_lt_pl`, `flow_pl_lt`, `flow_se_pl`, `flow_pl_se` | Cross-border flows per section, in the sign PSE publishes |

<Aside type="caution">
  `rce_pln` is **not** the day-ahead price. It is another series: in a comparison its correlation with `csdac_pln` was 0.98 and the mean absolute difference 43 PLN/MWh. Use `csdac_pln` as the SDAC price and as a forecast target.
</Aside>

The history of the tables starts in mid-June 2024 for load, SDAC, RCE, generation and `pdgsz`. A range before it returns no rows (with a warning). Values PSE has not published yet are NaN.

PSE's tables not offered yet, because their publication lag changed during the history or they have no usable timing: the balancing tables (`sk`, `cor`, `energy-prices`), `poze-redoze` (curtailment, mostly empty) and `unav-pk5l` (unavailability, whose archive is the latest revision only).

## Time index

- PSE stamps a 15-minute row with the **end** of its period: `dtime` (local) and `dtime_utc`, with `period` and `period_utc` giving both ends. The source reads `dtime_utc` and moves it back 15 minutes, so the index is the UTC **start** of the period, as in every source of the library. The row of 00:00 - 00:15 Warsaw time is at 00:00 local.
- A 23-hour day has 92 rows and a 25-hour day 100; there is no gap or repeat in UTC. Convert with `TimezoneTransformer("Europe/Warsaw")`.
- `business_date` is the local date of the period's start. The source asks for the local days that hold `[start, end)` and clips to the range, so a sub-range gives the values of a larger one.
- `pdgsz` is hourly and stamps the hour's start. Its value is repeated over the four quarter-hours of the hour, so all datasets share the 15-minute grid. `ResampleTransformer(freq="1h")` turns the frame into an hourly one (mean).

### `pdgsz`: one value, the first version

The table keeps every version of an hour (`valid_from_ts`, `valid_to_ts`), about 36 per hour on average. The source takes each hour's **first** version, by its UTC publication stamp: a later version can be written on the delivery day itself, after a forecast issued earlier.

### `publication_ts` is not used

Every PSE row has a `publication_ts`, but it is the stamp of the **last write**: rows reloaded in bulk show the reload time (`kse-load` rows were stamped after the end of D+1 on 37.7 % of business days). The source doesn't use it, except to order the versions of `pdgsz`, and the rules below don't read it.

## Availability rules

`InformationSet.with_source_rules` (so every `Workflow`) gives the columns of a `PseSource` these rules, in `Europe/Warsaw` and with the prefix. A delivery day D is known:

| Column | Available from | [Class](/epftoolbox2/model-pipeline/information-set/#vintage-classes) |
|--------|----------------|-------|
| `load_fcst` | 09:00 on D-1 | `last_write_stamp` |
| `csdac_pln`, `rce_pln` | 15:00 on D-1 (over 365 days: median 13:47, 99th percentile 14:59, latest 18:00) | `last_write_stamp` |
| `usage_fcst` | 16:00 on D-1 (a quarter of the hours have their first version later, the latest at 19:00 in a year) | `row_stamp` |
| `load_actual`, the `his-wlk-cal` columns, the `flow_*` columns | 13:00 on D+1 | `last_write_stamp` |

So a forecast issued at 11:45 on D sees `load_fcst_d+1`, the prices of D, `csdac_pln_d-1`, and the actuals up to `load_actual_d-2`; it doesn't see `load_actual_d-1` (known at 13:00 on D). `load_actual` of PSE replaces the ENTSO-E default of that name, with a source in the pipeline. Give the sources a `prefix` when you combine PSE and ENTSO-E columns.

A backtest reads the last-written value of a `last_write_stamp` column, not what was out at the issue time, so a model that reads one can look better than it would have been live (see [vintage classes](/epftoolbox2/model-pipeline/information-set/#vintage-classes)).

## Requests and caching

- One request per dataset and 31 local days, with `$filter` on `business_date`, `$first=10000` rows a page and `nextLink` followed from page to page (a year of `csdac-pln`, 35 040 rows, takes about 3 s). A `nextLink` to another host is refused.
- The generic User-Agent `epftoolbox2` is sent. 429, 5xx and network errors are retried with backoff and `Retry-After`; any other error raises `PseApiError`, so a failed request never becomes a silent gap.
- `get_cache_config()` holds the datasets, the selected columns, the prefix and a schema version, so the per-source cache of the [data pipeline](/epftoolbox2/data-pipeline/caching/) is used and a change of any of them is a new entry.

sources:
