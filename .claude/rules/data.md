# Data sources, transformers, validators

## Source contract
- `fetch(start, end)` returns a DataFrame with a **UTC** `DatetimeIndex` covering at least `[start, end)`. Local time only appears after `TimezoneTransformer`. `DataPipeline` clips every source to `[start, end)` (cached or not), and a cached run is assembled from pieces fetched separately, so a fetch of a sub-range must give the same values as a fetch of a larger range.
- `get_cache_config()` must include **every** parameter that changes the output; a missing parameter means stale data is served silently. The cache key (`CacheManager`, Parquet files under `.cache/sources/<key>/`) hashes `CACHE_FORMAT_VERSION`, the source class and that dict. When parsing logic changes, add or bump `"schema_version"` in `get_cache_config()`; when the cache layout changes, bump `CACHE_FORMAT_VERSION` in `data/cache_manager.py`.
- The cache records only what a source returned, never the last `UNSETTLED_PERIOD` (2 days) before now; each file is read only inside its recorded range; writes are atomic and each key is locked (`filelock`) around fetch + write. A multi-column source's outer join can leave the merged row index running past where one column actually stopped (e.g. `load_actual` mid-outage while `price` keeps publishing); `covered_ranges` additionally caps the whole recorded range at one step past the last value of any column still being published (last value newer than `DISCONTINUED_AFTER`, 14 days) — an older last value is treated as discontinued and doesn't cap coverage. A source can also cap the recorded range itself: `df.attrs["settled_until"]` (UTC timestamp, documented on `DataSource`) marks its rows from that instant on as not settled, so they are returned but fetched again next time. `DataPipeline._fetch_source` reads it right after `fetch` (a clip or concat may drop `attrs`, and a timestamp in `attrs` breaks `to_parquet`) and removes it from the frame. The single-file cache stores the earliest one in its sidecar and does not reuse a file whose `settled_until` is before `end`.
- Unit tests never hit the network: mock `session.get` (patterns in `tests/data/sources/test_entsoe.py`, `test_open_meteo.py`). Real-API tests get `@pytest.mark.integration` and the `entsoe_api_key` fixture, which skips without `ENTSOE_API_KEY`.

## Serialization contract (YAML)
`DataPipeline._serialize_component` dumps every public attribute (skipping `session`, `console`, `logger`) and reloads with `Class(**params)`. So constructor parameter names must equal attribute names, and derived/internal state must start with `_`. New components must be registered in `COMPONENT_REGISTRY` in `pipelines/data_pipeline.py` (see the `add-component` skill). A parameter value that isn't a plain type (str/int/float/bool/None/list/dict, plus numpy scalars/arrays, tuples, ranges and `Path`, all converted) raises `TypeError` on save rather than being silently dropped.

`api_key` (and any component's declared secrets) is written as `${<SOURCE>_API_KEY}` by default and expanded from the environment on load; `save(path, include_secrets=True)` opts out and writes the literal value. Any string parameter may itself contain a `${VAR}` reference, expanded on load and preserved (not flattened to the expanded value) on resave. File-like parameters (`path`, `*_path`, `*_file`, `*_dir`) loaded from a relative path are resolved against the YAML file's directory, not the working directory, and are written relative to it again on save.

## Column naming (relative to the row's local date D)
- `x_d-k`: value of `x` on D-k (LagTransformer, positive lag). `x_d+h`: value of `x` on D+h as known on D (negative lag, Open-Meteo forecasts, model targets). Hourly/minute lags use `h`/`min` units, e.g. `price_h-24`.
- Day lags shift by **local calendar days** (`shift_calendar_days` in `epftoolbox2/_date_utils.py`, shared with the model's target shift): same wall-clock time on D-k; the hour skipped in spring is NaN; the repeated autumn hour maps occurrence to occurrence, else to the first occurrence (the model's targets keep NaN there instead, see `BaseModel._shift_index_by_calendar_days`). `h`/`min`/`s` lags, and any frequency that isn't whole days (`"24h"`, `"15min"`), are elapsed time and never named `d`. Day lags need a local index: run `LagTransformer` after `TimezoneTransformer` (it warns on a UTC index). The skipped spring hour gives NaN in `x_d-k` at 02:00 on the day k days later, so the model skips those forecasts (hourly with `d-1` and `d-2`: 14 a year).
- `DSTNormalizeTransformer` (optional) turns the local index into naive wall-clock time with 24/96 slots a day (Lago et al. 2021: repeated hour averaged, skipped hour = mean of its neighbours, both on the same day; `is_dst_adjusted` flags them). Run it after Timezone/Resample and before Lag; after it, day lags and the model's shifts are plain whole-day shifts and no forecast is lost to DST. Values on flagged slots are synthetic, including actuals.
- Open-Meteo uses the **previous-runs** API: `{prefix}_{col}_d+i` at row t is the forecast for t+i days issued about i days earlier, and rows later than now+13h are dropped. Never switch a backtest to the plain forecast/archive API — it returns latest or observed values, i.e. look-ahead.

## ENTSO-E specifics
- Document types: A65/A16 actual load, A65/A01 day-ahead load forecast, A65/A31 week-ahead daily min/max, A75 actual generation, A69 wind/solar day-ahead forecast, A44 day-ahead prices, A61 day-ahead forecasted transfer capacity (`transfer_capacity`, needs `neighbours`), A68/A33 installed capacity (`installed_capacity`, P1Y at local 1 January, carried to `start` via `_PERIOD_COLUMN_PREFIXES`). Parsing is `xml.etree` with namespaces stripped; responses with a DTD are refused.
- `prefix` is applied last in `fetch`, after `_clip`, so internal column names (`_PERIOD_COLUMNS`) stay unprefixed. `neighbours`/`prefix` enter `get_cache_config()` only when set.
- A77/A80 unavailability is deliberately not offered: the API gives the latest revision, and with `mRID` all revisions but with `createdDateTime` rewritten (2024 outages dated October 2025), so values known at issue time cannot be rebuilt.
- `fetch(start, end)` returns [start, end). Daily columns (`_PERIOD_COLUMNS`) whose day covers `start` are re-stamped at `start`.
- curveType A03 omits a point that repeats the previous one: every Period is expanded to positions 1..N from its `timeInterval` and forward-filled (also trailing positions). A01 gaps stay missing.
- A31 comes as one Period per request starting at local midnight of the first requested day (verified for PL and DE_LU in winter, summer and across both DST switches in 2024), and this holds for every area, not just CET/WET ones: the period always starts at *that area's own* local midnight, whatever its UTC offset. P1D positions are mapped onto local calendar days of the area (`AREA_TIMEZONES`, default Europe/Brussels), so a week with the autumn switch (169 h) still has 7 positions. When this source is part of a `DataPipeline`, each P1D value's own local day D is then re-anchored to *the market zone's* local midnight of D, not this area's own (`EntsoeSource._daily_zone`, bound via `DataPipeline._bind_component_timezones` like `CalendarSource`/`OpenMeteoSource`, though this source has no zone parameter of its own to conflict with) — a neighbouring area combined into a market pipeline (`EntsoeSource("FI", ..., prefix="fi")` inside `DataPipeline(timezone="Europe/Warsaw")`) would land its daily value an hour off the market's own day, and on the wrong calendar day around a DST switch, since FI/EET and PL/CET switch at the same UTC instant but never share a UTC offset. Standalone use (no `DataPipeline`), or an area that already is the market's own, keeps the area's own midnight stamping (a no-op in the second case) — see `TestWeekAheadDailyMarketZone` in `tests/data/sources/test_entsoe.py`. `TimezoneTransformer.daily_columns` snapping is **not** a no-op in general: its default `daily_anchor` is the resolved `target_tz` itself (DST/timezone review finding 1), matching where a same-pipeline `EntsoeSource` always anchors A31; a fixed `"UTC+02:00"` anchor would silently misplace every value in EET/EEST zones (FI, EE, LV, LT, BG, GR) every summer and every value, year-round, in a fixed-UTC+3 zone (e.g. Europe/Istanbul) — see `TestDefaultAnchorIsTargetZone` in `tests/data/transformers/test_timezone.py`. Its `daily_columns` also match a `f"_{name}"` suffix, so a prefixed neighbour's column doesn't need listing by name. `epftoolbox2.information_set.source_rules` follows the same anchor: an `EntsoeSource` with `"load"` in `type` gets its own `load_forecast_daily_min`/`_max` weekly-availability rule (prefixed the same way) evaluated in `EntsoeSource._daily_zone()`, not the built-in default's `Europe/Brussels` — otherwise a market whose offset differs from Brussels around midnight (e.g. Helsinki/EET in winter) could flag one hour of the delivery day's rows differently from the rest, because that hour's wall clock falls on the *previous* day when read in Brussels time.
- Prices: only classificationSequence 1 or absent (SDAC). DE_LU/AT also publish sequence 2, a separate 15-minute auction (EXAA), on the same timestamps; never use it as SDAC. From 2025-10-01 PL and DE_LU publish only 15-minute SDAC prices, before it only hourly. Output is one grid: hourly with `prefer_15min=False` (complete quarter-hours averaged), 15-minute with `True` (hourly periods step-filled).
- A75: series in `outBiddingZone_Domain` are consumption (pumping; for AT every type, mostly zeros) and go to `generation_<type>_consumption`, never into the generation column.
- The API key travels in the `SECURITY_TOKEN` header, not the URL; error messages are redacted and carry the Acknowledgement `<Reason><text>`. 429/5xx/network errors are retried (`MAX_RETRIES`, honouring Retry-After); anything else raises `EntsoeApiError`, so a failed chunk never becomes a silent gap.
- `get_cache_config()` has `prefer_15min`, `schema_version` (`SCHEMA_VERSION`), and, only when `"load"` is requested, `daily_zone` (the resolved A31 anchor, see above — a pipeline bound to a different market zone must not share a cache entry with another); bump `SCHEMA_VERSION` whenever parsing output changes.
- Publication deadlines (Reg. 543/2013) vs 12:00 CET gate closure, i.e. what a forecast issued on D may use, are tabulated on the docs page `docs/src/content/docs/data-sources/entsoe.mdx`. Short version: `load_actual` and `generation_*` actuals only `_d-1` and older; `load_forecast` up to `_d+1`; `load_forecast_daily_*` up to `_d+2` (`_d+3` after 10:00); `generation_*_forecast` only `_d+0` and older.

## Known issues (don't fix as a side effect of other work)
- Open-Meteo `{prefix}_{col}_d+i` columns are shifted by `24h * i` in UTC (`open_meteo.py`, `_parse_weather_data`), not by local calendar days, so around each DST switch they point one hour off the model's targets (23 rows per switch per i). `shift_calendar_days` is the fix.
