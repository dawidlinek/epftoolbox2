# Evaluation, results, exporters

- `Evaluator.compute(df, **kwargs)` gets one model's rows for one group plus `model_dfs`: every model's DataFrame for the same group. The frames are **keyed**: `run_date`, `target_date` (datetime64), `hour`, `horizon` (int), `prediction`, `actual` (`FORECAST_KEYS` in `evaluators/base.py`). A key that no record of a model carries is left out of its frame (records passed as plain lists may lack them), so evaluators that need keys must check. Relative metrics (rMAE) read their benchmark from `model_dfs` and must align on the keys. Existing evaluators ignore the extra columns.
- `Evaluator.compute_group(model_dfs)` is what the report calls, once per table group and evaluator; by default it loops `compute`. Set-level evaluators (`DMEvaluator`, `MCSEvaluator`, base `SetEvaluator`) override it. A dict result becomes several columns named by `column_name(key)` (`"{name} {key}"`), so a dict from `compute` alone is enough for several columns (`EconomicEvaluator`). A second evaluator on a column of a dict result raises; two one-value evaluators of one name (two `rMAEEvaluator`s) keep the last with a warning. Exporters get the columns from `metric_columns(table)`, never from `evaluator.name`.
- Every `EvaluationReport` path builds its frames with `_model_frames()` (one pass per model, compact dtypes: these can hold millions of rows; a results file is parsed again only when its size or mtime changed, and each table gets a deep copy of what was read) and runs evaluators through `_apply_evaluators()`: `summary()`, `compute_all()` (single pass, used by exporters) and `_grouped_table()` (the `by_*` methods) all go through them. A change in grouping or evaluator calling convention goes there; `tests/test_report_consistency.py` checks that the paths agree and that evaluators receive keyed frames from each.
- Records are written in the order tasks finish, which varies between runs of the same study, and float sums depend on the order of their terms. `_model_frames()` therefore sorts each model's rows by `RECORD_ORDER` (the forecast key `run_date, target_date, horizon, hour`, then `prediction`, `actual`, `day_in_test` for ties) before any evaluator sees them; `iter_details()` and `predictions()` use the same order. Anything that reads records for a number must go through that, not through file order. `tests/results/test_report_order.py` shuffles records and demands bitwise-identical tables and details and identical exporter files (the CSV and terminal checks are regression guards: they print no unrounded sums).
- Exporters only format what the report computed; they must not compute metrics themselves. `CsvExporter`'s `extra_columns` join by target date and period, so the source is checked with `check_index` at the results' freq (every hour of a date is period 0 at 1D and would multiply the rows; a finer source at 1h or 15min would too), over the file's target dates for the spacing; a source of another resolution raises, and the repeated autumn hour joins its second occurrence (`drop_duplicates(keep="last")` in time order), the row `issue_row` forecasts from. `tests/test_csv_extra_columns.py` holds it, with the files written before the check in `tests/fixtures/csv_extra_columns/` (a change to the join must leave them byte-identical). `TerminalExporter` prints `report.availability()` first, whatever `show` says, when it has rows, and after it the rows of `report.training_days()` with thin forecasts (no more days than predictors).
- A manifest holds `skipped`, window -> reason -> count, only when a run skipped something (`record_skips`, written when the run finishes, so a crash leaves what was there and `missing` beyond the reasons means a crash). A resume or a run naming one window replaces that window's counts. `ModelPipeline.report()` reads them back, and for a plain period other than the manifest's leaves them out, as they can't be split by day. Nor can they be split by horizon: a report told a list of horizons other than the run's (`ModelResultRef.horizons`, `horizons_of`) leaves them out too. They never refuse a resume and stay out of `manifest_digest`. `report()` counts `produced` through `iter_records`, not by the file's lines.
- Result records (JSONL) have keys `run_date, target_date, run_weekday, hour, horizon, day_in_test, prediction, actual, coefficients, freq`, plus `window` in a run with validation (no `window` means `"test"`), `predictor_list` for a predictor function of `ctx`, `training_days` and `matching_days` for a `train_on="matching"` list, and `newest_target_day` (the newest target date of the training span, D + min(k, h-1); not necessarily a target that trained, since it can be a slot the clock skips or a missing value, whose row drops) for a model with `newest_target="published"`, and `refit_anchor` (the ISO date of the anchor whose fit made the forecast) for a model with `refit`. A `NaiveModel` record has the plain keys with `coefficients` `[]`; its keys whose value isn't published by the issue time are skips (`not_published`), not records. `freq` is `"1h"`, `"15min"` or `"1D"`; a daily run's records have `hour` 0, the shape `aggregate()` writes, so every path that takes aggregated records takes them. Old result files must keep loading; add keys, don't rename them.
- **D4's keys and skip records** (step 5a, `results/store.py`). Every record a model writes ends with `status` (`"ok"`), `list_hash` (`context.list_hash` of its list, for fixed lists from `config["fixed_list_hashes"]`, so the hash a function returning that list gets), `refit_anchor` (its `run_date` without `refit`; a refit record keeps its own after `freq`) and `revision` (1), appended by `with_status` after every key it had, whose order and values stay byte for byte; an ensemble's end with `status` and `revision`. A key without a forecast is a **skip record** in the file (not in memory): the key fields, `prediction` null, `actual` the issue row's target (null without the row), `coefficients` `[]`, the four keys with the reason as `status`, and `detail` after them when the reason has one; `BaseModel._skip_writer` builds them in the parent for parent-side skips and from each worker's `(task, reason)`, with the worker's list, window and target. **Readers** (`read_records`, under `ResultStore.iter_lines` and `ModelResultRef._records`, the only two) give one record per key `(hour, horizon, run_date)`: the highest `revision`, within it a forecast over skip records and the first forecast; a repeated forecast equal to it but for D4's keys is dropped with one warning per read, a different one raises `ValueError` naming the file and a key (`duplicates="first"` on `read_records` alone, for repair tools, reads the first); two passes over one open file (key, revision and status off each line without parsing it, `_key_fields`, then only the chosen lines parsed, in file order, each checked against what the first pass read: a file written in place meanwhile raises, one `os.replace`d is read as opened), so memory is what the caller keeps; a damaged line no key chooses isn't parsed, so isn't reported; and only `status` "ok" or none by default (`statuses=None` for every key's); results held in memory are filtered by status only, never deduplicated (plain lists may lack keys, and rMAE/DM/`aggregate()` refuse a repeated key there). So every table, count, ensemble and exporter reads what it read before. **Resume:** done keys are those whose chosen record under the readers' rule is a forecast (`ResultStore._completed`, also `has_results()`, what `has_existing_results` is); a skipped key is retried and gets a new skip record only when its newest one has another status; `save`/`save_skip` write at the key's highest revision on file (`_revisions`), so a resume's forecast is the one read. `off_the_clock()` reads the clock's fields alone and `EvaluationReport._result_freqs` one line a file (`ModelResultRef.first_record`): never a whole file of coefficients. A half-written last line (no newline, not a record) is skipped with a warning on read and cut off with a warning naming its bytes when a writer opens with the lock (or before its first write without one); a malformed line before it raises with its number. Files are read as bytes decoded UTF-8 and written with `encoding="utf-8"`. **Lock:** `BaseModel.run` opens its store with `lock=True` (`<name>.lock`, our own `fcntl.flock` in `_hold_lock`, so EAGAIN/EWOULDBLOCK/EACCES mean held and any other errno warns whatever filelock's version; opened read-write, else read-only, since flock needs no write access; its descriptor closed in forked children by an `os.register_at_fork` hook, never unlocked there; filelock only where there is no `fcntl`) and closes it in a `finally` after the manifest's `record_skips`, so a second writer raises `ResultsLockedError` naming the lock; a file system refusing locks warns. Manifests record `record_schema` (2) as provenance. `tests/results/test_record_status.py` holds all of it; the bitwise check against the commit before is `epftoolbox2-research/library_check_step5/record_status/`.
- **Parquet results** (step 5b, `results/parquet_store.py`, `results/parquet_schema.py`). `run(save_format="parquet")` writes `<name>.parquet/` (a directory beside `<name>.manifest.json` and the same `<name>.lock`): `year=YYYY/part-<run id>-<seq>.parquet` (zstd, one row group, sorted stably by run_date, hour, horizon) and `_catalog.jsonl`, one line per committed part (file, rows, bytes, first/last run date, sha256, CRC-32 of the line). A part is written to a temporary name and renamed, then catalogued; readers read only the parts the catalog lists and no later line supersedes, so a crash leaves an orphan nobody reads (`verify` notes it, `compact` removes it); a torn last catalog line is skipped with a warning and cut by the next writer with the lock, a damaged one before it raises. Schema: one column per record key (`parquet_schema.COLUMNS`, fixed) plus `_keys`, each record's keys in order, so a record converts both ways exactly (null vs absent, key order, float bits); a key outside the schema raises at `save()`. **One reader rule for both formats**: `store.read_records` and `iter_file_records` dispatch on the `.parquet` suffix to `parquet_store.read_records` (`choose`: highest revision, first forecast in catalog order, else the last skip record; repeats compared with `forecast_text`, the same message as JSONL), so every table, count, resume and ensemble reads Parquet through the readers they always used. `ModelResultRef.frame(columns)` gives what `iter_records(columns)` gives as a DataFrame without dicts (the same rule, filters and clock, vectorised in `_keep_rows`; each column typed as a list of record values would make it, `parquet_store._series`), None for JSONL or memory; `EvaluationReport._model_frame` takes it when not None, `ModelPipeline.report` counts through `count_records`, and `_cached_frame` fingerprints the catalog (`store.fingerprint_path`). `tests/results/test_parquet_store.py` checks the frame path against the dict path and every table bitwise from a converted twin. **Formats:** `results_path(save_dir, model)` finds either and raises `ResultsFormatError` for both; a store opened with the lock refuses the other format beside it (`check_no_other_format`, naming `epf results convert`), and `ModelPipeline.run` checks every model before any fit; ensembles are always JSONL. The manifest records `save_format: "parquet"` (provenance, `_PROVENANCE_FIELDS`, so digests don't move; no key for JSONL); `convert` rewrites it. `save_coefficients=False` (run, Workflow, `BaseModel.run`) writes `coefficients: []` in the store and no other key; the manifest records `save_coefficients: false` (no key with the default) in `_COMPARED_FIELDS`, so a resume with the other setting raises. **A key is done once on file** (`_Store._written`, from a JSONL batch or each committed part's keys; `_saved` until then, which `save_skip` reads): a failed write is the store's error while its I/O lock is held (`StoreWriter._fail`, also for `_convert`; a JSONL store's own thread keeps it for `flush()`), raised by every later `save`/`flush`/`close` (`_Store._failed`: the store writes nothing more, `_tail_checked` reset, so a half-written line or catalog line stays last for the next writer to cut), and its keys stay pending, so `produced` never counts an unwritten forecast. A torn catalog line is cut before the first part whatever the lock (`_tail_checked`). Parts, the catalog and the directories are synced (`_sync_directory` after a rename, a new year directory, a new catalog); a catalogued part missing raises `MissingPartError` (a ValueError naming `epf results verify`). Part files are not reproducible between identical runs (splits follow the age flush and the buffer cap), records are: compare records, never part bytes. **Locks held in this process** (`_HELD_HERE`): a model's own lock, a group's file and the models a group took; a second writer in the process is refused from it without opening the file, and `_group_file_held` consults it before probing (on NFS a probe of a POSIX-emulated flock this process holds would release it); a stale group file is never removed by anyone but its writer. An epftoolbox2 older than 5b doesn't read group names: two library versions writing one save_dir is unsupported. **`StoreWriter`** (`results/store.py`): one thread for many stores (`open(path, ...)`), JSONL batches within 0.1 s, Parquet buffers per (model, year) (`_YearBuffer`: Arrow chunks the writer's thread converts 4,096 records at a time, `_convert`, then the dicts not yet converted; a part is cut from both, slicing a chunk at a whole-part boundary) written at `PARQUET_ROWS_PER_PART` rows (whole parts only), `PARQUET_FLUSH_SECONDS` of age or `PARQUET_MAX_BUFFERED_ROWS` in the writer (largest first), `flush()` four stores at a time, every open store, so it also waits (on each store's I/O lock) for a batch the thread took and is still writing: on return every record saved before is on file and done (5h: a group's model read as producing nothing otherwise), files opened only while written (at most `max_open`, 64), and one `_GroupLock` for all its stores: its own flock file, named in each model's lock file under that file's flock, which `_hold_lock` reads too, so a model has one writer whether held alone or by a group; a lone `ParquetResultStore` has a private writer and the plain lock. `epf results convert|compact|verify` (`cli.cmd_results`) hold each model's lock; `compact` keeps every record and is idempotent. pyarrow is imported inside functions only (`pyarrow.parquet` stays unloaded by `import epftoolbox2`; pandas loads `pyarrow` itself). The measurements are `epftoolbox2-research/library_check_step5/parquet_store/`.
- **Live directories** (step 8c, `results/live.py`; `epftoolbox2-research/library_check_step8/feat-live-store/`). A directory is live when it holds `live.json` (`store.is_live_dir`); `live.lock`, `issues.jsonl` (call lines; a commit is `committed: true` with `finished`, the instant it became visible, and `issued_at`, `snapshot`, the call's `deadline`), `delivered.jsonl` and `issues/<issue>/r<n>/` sit beside the models' files, and `_models_in` leaves the two logs out. **Records**: a live revision's store (`LiveResultStore`, `live_parquet_store_class()`, `_Store._live`) stamps every record with `with_live`: `revision` r in place, then `issued_at`, `mode` "live", `snapshot` after every key; its `_load_existing` reads nothing. The three are Parquet columns (`parquet_schema.LIVE_COLUMNS`: `issued_at`/`snapshot` strings, `mode` category) of a part with a live record alone (`to_table` picks `arrow_schema(live)`), so a backtest's parts are the base's bytes; `_conform` gives a part without them nulls on read, `_concat_parts` conforms only parts of different schemas (compaction keeps a backtest's); `mode` is a rule column. **Numbers**: `next_revision` = 1 + max over the day's call lines and revision folders, and over every model's records (`store.max_revision`, committed or not) only for a day without any folder (a record scan is 0.65 s per model-year); `begin` appends a `"begun"` line (`BEGUN`) and then makes the folder (`mkdir` without `exist_ok`), both before any record, so no number is reused after any crash; only removing both by hand could, and then `store.check_marks` raises on a visible record whose `issued_at`/`snapshot` isn't its commit line's (`Commit.marks`, carried in `visible()`'s values and passed as `marks` to the JSONL second pass and Parquet `chosen_rows`). `commit` closes and fsyncs the stores, then appends its line synced (after the call's deadline: `LiveLateError`, nothing committed); anything a commit raises poisons the revision (`_poisoned`: `commit`/`open` raise, `fail`/`abandon` alone); `fail` writes `committed: false`, `abandon` nothing; `LiveRevision` is a context manager that abandons what it leaves unfinished, and `hold()` abandons every revision of its block (`_begun`) before releasing `live.lock`; a model opens once per revision (`_opened`). A JSONL store's own writer is started again by `flush()` (it used to stop, dropping what was saved after) and a closed store refuses `save` (`_Store._closed`); `_read_log` skips a torn last line with a warning and `_append_line` cuts it first. **Readers**: `read_records(..., committed=, issued_by=)` turns issue day -> revision -> commit instant (and a cut-off) into visible (run_date, revision) pairs (`visible_revisions`); the JSONL first pass and Parquet `choose` drop every other line before the per-key rule (so an invisible higher revision never hides a visible one), then keep each issue day's highest revision with a record of it in that file alone (`_day_top_revisions`, `choose`): a key it lacks has no record, never a lower revision's; and the second pass / `chosen_rows` raise `LiveDirectoryError` for a live record read without `committed` or a non-live one read with it; `check_reading` refuses a file in a live directory without `committed` (`read_frame` too). `LiveStore.visible(policy, cutoff)` decides per issue day among commits with `finished` at or before the cut-off ("deadline": `live.json`'s `deadline` in its `issue_timezone`, and each commit's own `deadline`; with no deadline in `live.json` only commits with their own, made by it: fail closed; a mapping's keys go through `store.issue_day`, a day it lacks is `NOTHING_VISIBLE`, `cutoff_of_day`): "latest" all, "first" the lowest alone, "delivered" those up to the newest delivery at or before the cut-off of a visible revision; `pending=` gives a call's own uncommitted revision alone on its day (a member not yet flushed has nothing, never an older revision: 8e flushes every member before an ensemble of the revision reads them). `live_reading` (every `ModelResultRef` read) warns when its cut-off leaves out committed revisions of the ref's days that `cutoff=None` would read. `ModelResultRef(policy=None, cutoff="deadline")`: None reads a live directory as "latest", a policy on a backtest's results raises; `iter_records`, `frame`, `first_record` all read through `_committed()`; `report._cached_frame`'s fingerprint adds `live_fingerprint` (empty for backtests). **Refusals**: `ModelPipeline.run`/`report` (`refuse_live_directory`), a backtest store with the lock in a live directory and a live store outside one (`_Store.__init__`), `LiveStore.init`/`hold` beside a backtest's files (`refuse_backtest_files`), `check_and_write` on a live manifest and `check_and_write_live` on a backtest's. **Issue days**: `store.issue_day(value, zone)`: an aware instant is its date in `live.json`'s `issue_timezone` (`LiveStore.day`), raises without one. **Identity**: `init` compares values after the JSON round trip (`_as_json`). **Manifests**: `Manifest.mode` ("live", no key for backtests, not compared, so no digest moves); `check_and_write_live` sets `save_format`/`save_coefficients` as `check_and_write` does and compares `_COMPARED_FIELDS` but `LIVE_UNCOMPARED` (`data_columns_hash`, `history_ahead`), `chained_differences` and `ensembles._compute._what_decides_availability`. **Lock**: `LiveStore.hold()` is `_hold_lock` on `live.lock` (`LiveBusyError`, status "busy", exit 75; another `LiveStore` in the process counts as another holder); a model named "live" shares it (its store opens without its own lock, `_lock_model` skips it inside `convert`/`compact`, which hold `live.lock` in a live directory; `verify` reads every committed revision). `ModelPipeline.mark_delivered` holds it (a dry run with `create=False`, so no lock file appears) and refuses an uncommitted or unknown revision. `tests/results/test_live_store.py` holds all of it against a hand-made oracle, JSONL and Parquet.
- **Vintages** (`results/vintages.py`). A run with an information set has `ModelResultRef.vintages`: one row per input and per column a function read through `ctx` (`predictor`, `series`, `class`, `ctx`), None when no class is declared (so manifests of user-only rules don't move). The manifest stores them as `vintages`, never compared, out of `manifest_digest` (ensemble manifests don't move), merged on resume under the same information set (`_keep_vintages`). `report()` reads them back (`read_vintages`), `aggregate()` and `split_by_window` keep them, an ensemble's ref has its leaves' union. `report.vintages()` shows them, `TerminalExporter` prints the revised rows after the availability listing. `tests()` (model, benchmark pairs), `compare()` (a, b), `leaderboard()` (all) and `_summary_table`/`_grouped_table` with a `DMEvaluator` (pairs with its benchmark) call `flag_mixed_classes`: two models reading one `series` with different declared classes warn and set `df.attrs["vintages"]` (series -> model -> class); "unknown" never counts, and a table without a mix gets no attribute (decision 18: warn, never refuse).
- **Provenance** (step 6a, `models/_cards.py`). `ModelResultRef.provenance` is a carded model's `{card, runtime, weights}` (`run_provenance`: the manifest's when the run wrote one, else the model's; `read_provenance` from a manifest in `report()`; carried by `split_by_window` and `aggregate()`), None for core models and ensembles. `report.provenance()` (`provenance_frame`, `PROVENANCE_COLUMNS`) is one row per carded model, with the verdict of each window recomputed from the card and the run's windows (`report.windows`, else the ref's `test_start`), so a report of either window shows both. The terminal exporter prints "Model provenance" (empty columns dropped, `licence_url` left out), `CsvExporter` writes `<stem>.provenance.csv` next to its `path` (`provenance_path`, so two exporters in one folder don't collide) and `ExcelExporter` a last "Provenance" sheet, each only when the table isn't empty, whatever `show`/`sheets` say; with no carded model nothing of an exporter's output changes (`tests/fixtures/report_pin`).
- **Horizons.** `ModelResultRef.horizons` is what a ref plans: a run's ref has it for a list that isn't 1…`horizon` (None otherwise), a `report()` ref always (told neither `horizon` nor `horizons`, `report()` plans what the manifests record, `_stored_horizons`, and models with different lists raise), and `iter_records` reads only records of those horizons, so `report(horizons=[3])` of a `[1, 3, 7]` run is horizon 3 alone and `report(horizon=3)` of a horizon-7 run is horizons 1 to 3. `Manifest.horizons` is written only for such a list and compared on resume. An ensemble reads every record its members have on file (`_read_member` drops the filter, so its file never depends on what a report names), compares the members' lists (`horizons_of`), and plans the list its members' refs plan, so one report plans one list for members and ensemble alike. A `top` choice pools every horizon on file, also in a report told fewer: it is no look-ahead, but a `[1, 3, 7]` run can choose another member than a run of every horizon.
- **Issue days.** `ModelResultRef.issue_days` is the weekdays (`date.weekday()` numbers) a ref plans, None for every day, and `iter_records` reads only records whose `run_weekday` is one of them. `Manifest.issue_days` (names) is written only when set and compared on resume. `report()` takes it from the manifests when not told (`_stored_issue_days`; results with no manifest don't count) and raises `ValueError` for models run on different weekdays; told, it plans and reads those weekdays, so `report(issue_days=["friday"])` of a run of every day is its Fridays, and `read_skipped` gives no reasons when the weekdays differ from the run's. An ensemble drops the filter when reading members (`_read_member`), refuses members run on different weekdays (`_check_members_agree`), and plans the weekdays its members' refs plan (`like.issue_days`), as for horizons.
- **Windows.** `ModelResultRef.iter_records` is the one way to read records, and it holds the filter: dates, `window`, and `target_before` (a validation ref leaves out forecasts for the first test issue day or later, a look-ahead when picking by hand; `split_by_window` counts them in `skipped` as `target_in_test`). A new report method must read through it (`_iter_ref`, `_model_frames`), or a record of the other window becomes reachable; `tests/pipelines/test_validation_test.py` compares every table with the plain runs. A ref of a window has that window's `count`, `produced`, `skipped`, `predictor_lists` and `availability_listing`. One report holds one window: `__init__` raises on refs of several, and takes the ref of a whole run apart itself (`by_window`). `join()` refuses reports on different windows or, for a run with validation, other days of one or another cut (a plain report next to one with windows is compared too, and `aggregate()` keeps a plain ref's period for that); `aggregate()` stays on its window by tagging its records.
- **Scoring by period** (step 7b, `results/breakdowns.py`, `evaluators/_days.py`, `evaluators/shape.py`, `evaluators/normalised.py`). `aggregate(freq, agg, peak_hours=(8, 20))`: the four day aggregates keep their path (`daily_aggregate`, bitwise as before); `"peak"`/`"offpeak"` (`block_aggregate`, 1D only) take the mean over the periods of the block by local hour (`id // per_hour`), a day counting when the model has every block period the date has (the clock's with a zone, else the ids any model has on that date) finite; `freq="1h"` (`hourly_aggregate`, 15-minute results only) needs all four quarter-hours finite (`whole_hours`, the one place that rule lives: the hourly aggregate, `ShapeMAEEvaluator` and `error_split` use it), counts `incomplete_hour`, and its ref keeps the zone. Both leave out evaluators with `source_columns` (`ScaledMAEEvaluator`), the 1D one also `EconomicEvaluator`. `ModelFrames.freqs` (`{model: freq}` from `_result_freqs()`, once per table) tells evaluators the frequency: `ShapeMAEEvaluator` is NaN unless "15min" (by the ids only when called without it). An evaluator's `source_columns` are joined to the frames by `_with_source_columns` in `_summary_table`/`_grouped_table` (no evaluator asks: the frames are untouched), with `source_table`/`source_values`: `CsvExporter(extra_columns=)`'s join (check_index at the results' freq, local wall clock, the repeated hour's second row), written once more there, which `tests/test_report_period_aggregates.py` pins with an autumn flag. `by_column(column, bins)` is `_grouped_table` with a label from that join (bins closed on the left, `no_value` counted); `metric_columns` leaves `attrs["by_column"]` out. `error_split()` is per model on its own whole non-switch days (finite ids exactly 0-95, and with a zone not a date whose clock changes, `switch_dates`). Blocks read ids as local hours, so they drop days numbered otherwise: a record of a slot its date lacks, and without a zone the dates `numbered_by_the_clock` blanks (an id past 23:59, a Sunday numbered exactly 0-22); `check_period_ids` raises on ids past the results' frequency (blocks, `ShapeMAEEvaluator`). `aggregate("1D")` refuses zone-less refs with `incomplete_hour` (an hourly aggregate that dropped hours: a dropped autumn 02:00 would pass as a spring day). `check_source_zone` (breakdowns, keyed by `zone_key`: the name, or `str` of a zone without one, as a manifest writes `data_timezone`) refuses a source whose index zone isn't the refs' zone (when they have one), for `_source_table` and `CsvExporter`'s `extra_columns` join alike. Block and hourly aggregates refuse zoned refs with `off_the_clock() > 0` (a spring day numbered 0-22: the reader drops id 2 and the rest would pass for the clock's day). `ModelPipeline._check_source_columns` refuses a column the data lacks before any fit (`run`, and `Workflow.run` for array tasks) and `report(save_dir)` without data; `Workflow.report()` loads the data for such evaluators. Excel sheet titles are unique per workbook (`_sheet_name`, `~2` suffix after the 31-character cut). `NMAEEvaluator` divides by the mean actual of the forecasts with a finite prediction and actual, never of every actual, and is NaN when that mean is 0. Tier S: `tests/reproductions/` scores the resolution (R1 honest, R3 derived) and renewables (experiment 2 ridge, experiment 1 DE) stored forecasts with library calls only; the study's Newey-West averages autocovariances over n - k (resolution `evaluate.dm_test`), the library's over n, so those DM cells are checked against the usual estimator and the study's verdicts, not to 1e-10; some cells of the reports were rounded twice from a rounded printout (24.1648 printed 24.165, then 24.17), and one is misprinted (renewables AT H2-2025 A69 13.63 for 13.636), which `tables.json` records.
- **Timestamps on the clock** (step 8a, `epftoolbox2.clock`): a manifest's and an ensemble manifest's `created_at`/`updated_at` and a Parquet part's name (`part-<YYYYmmddTHHMMSS>-...`) are `current_clock().now()`, so a `FakeClock` sets them; they are provenance, never compared. Real time on purpose (`SYSTEM` itself): the store writer's batching ages (`_YearBuffer.since`, `_loop`'s `now`) and idle waits, as a buffer is stamped in the caller's thread and aged in the writer's (whether a thread sees the caller's context depends on the build: free-threaded 3.14 copies it, the GIL builds don't), and the wait for another process's moment on a lock file (`_GroupLock._clear`), as that process runs on real time.

## Ensembles (`epftoolbox2/ensembles/`)
- An ensemble fits nothing and reads no data. `_compute.compute` reads its members through `iter_records` into one grid of forecast keys and writes records of a model's shape, so every table takes it as a model. The class only says what to choose and how to combine; it keeps nothing of what it chose, which goes to the manifest and `report.choices()`.
- **The average** is `np.mean` over the chosen members in member order, whatever the ranking, on the keys where all of them have a finite prediction, so `top=k` equals `AverageEnsemble(chosen)` bit for bit. A key a chosen member lacks is missing for the ensemble and counted as `member_missing` (planned minus produced minus `target_in_test`, so a key no member has counts too). It is never averaged over the rest.
- **Fallbacks** (step 8g, `ensembles/fallback.py`, `_compute._fallback_forecasts`). `FallbackEnsemble(members, *, per="day" | "key", name)` takes each (run date, target date, horizon) whole from the first member with a finite prediction on every planned key of it (`serve`: per day, a count of held keys against `planned`; per key, the first finite member). Planned is the clock's, `IssueCalendar`'s rule (`skipped_periods` of the run date and the target date, none without a zone), never the keys some member holds, so a key no member has leaves its day to no one (`member_missing`, from `_ref` as for an average). Skip records are not read (`OK_ONLY`), so the ladder moves past them; NaN/inf predictions count as missing. A day is never stitched from two members under `per="day"` (decision 10), so the Monday after a spring switch is lost by every rung reading `price_d-1` (its 02:00 reads the skipped hour; `price_d-7` a week later): pinned in the tests, documented with the remedy (a bottom rung without the lag, or `per="key"`). With `test_only` (a member is a `top` ensemble or over one) only test-window run dates are served, else a lower rung would serve every validation day. Records: a model's keys, then `rung` (0-based) and `member`, then `status` "ok" and `revision`; the manifest's params are `members` and `per`. `report(allow_missing=True)` passes over a fallback's member without results with a warning (`_ensembles_with_their_members`; an average keeps the old rule, and a ladder with no member left is left out): `compute` gives it an empty column (`_Member.absent()`, `missing: true` in `member_results`), so rung numbers stay, and no leaves; its ref's `passed_over` names them, which `forecast_counts().attrs["passed_over"]` shows (only when there is one). Its ref carries `ladder` (members in rung order, kept by `replace`/`split_by_window`, None after `aggregate()`), which `EvaluationReport.rungs(name)` reads: per rung `days`, `forecasts`, `mae_forecasts` and `mae`, and on the served keys where the rung-0 member has a forecast too (`common_forecasts`) `common_mae` and `rung0_mae`, identical keys with their count, plus each member's own `member_forecasts`/`member_mae`; exact sums (`math.fsum`); a member not in the report is a row serving nothing, in `attrs["absent"]`, with a warning. **Note for 8f:** within one revision a forecast wins over a skip record (`results/store.py`, the readers' rule), so a `check_failed` written at the same revision as the forecast it fails would leave the forecast read and the ladder unmoved: write it at a higher revision, or replace the records.
- **Frozen choices** (`ModelPipeline.frozen(save_dir)`, `pipelines/_frozen.py`). It first compares each `top` member's manifest with the pipeline's model of that name (`model_differences`: `model_class`, `predictor_layout_hash` from `_precompute_expanded_predictors` at the manifest's freq and horizons, or a predictor function's path, `training_window`, `model_params` as `build_manifest` writes it, keys with an object address skipped, `unit_kind`/`target_transform`, and of `training_cut` the keys the model sets, `_MODEL_CUT`: `refit`, `refit_epoch`, `refit_rules`, `binary_mask`, `newest_target`) and raises `ManifestMismatchError` on a difference, warning about fields a manifest lacks and about a predictor function's `fingerprint` that differs (a comment edit changes it too); then reports the `top` ensembles and their members alone (`_check_model_names` on the whole list first, and `_bases_from_the_whole_list` on the chooser, so a `ResidualModel` member keeps its base without reading it; no evaluators or exporters; it writes those ensembles' files as any report does), takes the row of the largest `segment` per ensemble from `choices()` and puts `AverageEnsemble(chosen, name=same, chosen_through=...)` in its place. `chosen_through` is the last day whose actual the choice read: min(validation end + the largest horizon on file, test start - 1), the validation end + the horizon without a test. A plain average with it makes no forecast issued on or before it (`compute` filters the keys; `_ref` counts them per window by the calendar as `chosen_in_sample`, apart from `member_missing`, with a warning), so a frozen pipeline saved, reloaded and run over the study's days is never scored in sample. The boundary passes on: `_compute_ensembles` keeps each ensemble's latest `chosen_through`, its own or a member's (`through`), and `compute(in_sample_through=...)` drops those keys after any branch, fallbacks and averages alike, nested too, so a fallback over a frozen average can't serve its in-sample days from lower rungs. It is written to YAML and to the ensemble manifest only when set (`_WRITTEN_WHEN_SET`), so no other file moves. `frozen_choices` (not in YAML) records it for 8c/8e's `live.json`; zone save_dirs raise. `tests/pipelines/test_fallback_ensemble.py` checks all of it against a pandas oracle and real runs; the mutants are in `epftoolbox2-research/library_check_step8/feat-fallback-ensemble/`.
- **What counts for choosing:** `Segment.serves` per segment, never a record's `window` tag, since a later segment's validation days are tagged "test"; on the keys every member holds, not only the chosen ones, with a finite prediction and actual. No common key raises. MAEs are compared after rounding to 12 significant digits, ties by member order and then the smaller k. A forecast belongs to the segment whose test period holds its `run_date`.
- A plain average has forecasts in every window on file. A `top` ensemble, and a plain average with one among its members (`ModelResultRef.test_only`), has test forecasts only: its validation score is in sample and lives in `choices()`, so a report's `.validation` doesn't look for it. A validation-only run gives it a row with no test period, no forecasts and no ref.
- **`choices()` test side and searches** (6p): an ensemble's row gets `test_mae` in `_compute.compute` after its manifest is written (the manifest records the choice alone, so ensemble manifests keep their bytes), from every forecast it has on file in the test period served, every horizon, as an exact sum (`results.ref.issued_mae`); `candidates` is its scored members, `gap` `test_mae - validation_mae`. A model of `tune.SearchResult.best` (its `_search`, recorded as manifest provenance `search` and carried by `run_provenance`/`read_provenance`) gets a row from `model_pipeline.search_choices`, keyed `{search}:{model}`, made by `run` and `report` from the run's test period on file. Rows are made once per run or report, so a report of one window, of fewer horizons or an `aggregate()` shows the same table: never compute them from a report's own refs. `kind` says which a row is. A searched model ranked below the finalists (a cheaper rung) gets no validation score or gap, and one whose run forecasts another target, horizons, freq or issue days than its search scored warns. A run refuses, before any fit, a searched model whose test starts on or before its `data_through` (`refuse_searched_on_test`). `_search` is read only as a dict.
- **Never resumed:** the file is recomputed by every `run` and `report` from the members' results and written atomically, so it can't go stale. Its bytes depend only on those results, not on what a report names or the order on file: `day_in_test` comes from the members, the manifest holds no planned count and no `test_start`. A member's manifest hash leaves out its provenance (`manifest_digest`), so a re-run with nothing new doesn't move it. A manifest with `"kind": "ensemble"` is not a `Manifest`, and no model resumes into one; an ensemble won't overwrite a file that isn't one.
- **What is compared between members** (`_check_members_agree`), always on the leaf models' manifests, so nesting can't get round it: target, horizon, freq, time zone and what decides availability in the `information_set` (issue time and zone, rules without their `note`, assumptions in any order, `use_defaults`; set against none raises too; `unknown` and the `availability` level don't count). Data: `column_hashes` (own predictors, the target and what a predictor function read through `ctx`, numbers as float64) for a column two of them read and for the target, through `test_end`, raises; so do the `actuals` hash and the `actual` of every key they share, exactly, and for manifests older than those hashes `data_columns_hash` on the same columns up to the same day. A different `frame_hash` with no shared difference warns, as a column one member alone reads can't be compared. A different `test_end` can't be compared and warns, and so do older manifests, members without one, and `data_unverified` (written by `check_and_write` only on a resume that accepted other data or had no manifest, and kept across resumes), by name. Results held in memory come from one frame and say nothing.
- **A choice says how thin it is:** the intersection rule stays, so a member's holes can decide the choice (`validation_share`, `limited_by`, warnings below `MIN_VALIDATION_SHARE`, `MIN_VALIDATION_DAYS` (distinct target days) and `MIN_VALIDATION_ISSUES` (distinct issue days, 28: four Fridays at horizons 1 to 7 reach 28 target days on four issues), in `_compute.py`).
- **Without ensembles** records, tables and YAML (`ensembles:` only when non-empty) are byte-identical. Manifests differ by `column_hashes` and `frame_hash` alone, which never refuse a resume. `FrameHashes` computes them once per `ModelPipeline.run` call: it belongs to that call, or a frame changed in place would get a stale hash.
- `report()` refuses a model whose file is an ensemble's (`is_ensemble_manifest`), `report(forecast_only=True)` reads and writes nothing, and the manifest is written before the records, so a crash between the two can't leave records that look like a model's.
- `allow_missing` leaves an ensemble with a missing member out, with a warning, and every ensemble made of it. Array tasks of a `Workflow` drop the ensembles; `report()` computes them.

## Comparing models (research correctness)
Two models are only comparable on the **same forecast keys** `(run_date, target_date, hour, horizon)`. Models with different predictors can produce different key sets because workers skip tasks with missing inputs. Report how many forecasts each model contributed whenever results are compared.

`rMAEEvaluator` does this: both MAEs are taken on the keys the model and the benchmark share (finite prediction and actual on both sides), NaN if they share none, `ValueError` if the key columns are missing, null or duplicated. The `forecasts` column of `summary()` is still each model's own count.

In the EPF literature (Lago et al. 2021, the original epftoolbox) rMAE is usually relative to a naive seasonal benchmark, and significance is checked with Diebold–Mariano or Giacomini–White tests. The Diebold–Mariano test is here; Giacomini–White is not.

### How the comparison code is built
- `evaluators/stats.py` holds numpy-only kernels that **pair by position and drop any index**. `evaluators/_compare.py` is the only thing that feeds them from forecasts: `LossPanel` puts every model of a group on one sorted grid of keys (one absolute-error column per model, NaN where it has no finite forecast), `compare_pair` works on a pair's common keys and `compare_set` on the keys of a whole set. `DMEvaluator`/`MCSEvaluator` and `EvaluationReport.tests()/mcs()/ranks()/compare()/leaderboard()` all go through them, which is why a column of `summary()` equals the matching table. Don't call a kernel on unaligned frames.
- **Exact clones** are one model to a test, and a `top=1` ensemble makes them as a matter of course. They are read on the keys compared. In a Holm family (`adjust_family`, `LossPanel.pair_clone_groups`) those are each model's keys with the benchmark: models with the same keys and predictions in that slice count once, and one whose slice repeats the benchmark tests nothing and doesn't count. A set (`LossPanel.clone_groups`) compares on the keys of all its models: `confidence_set` and `ranks()` run the kernel on `SetComparison.kept` and spread the result with `twin_of`, and an MCS takes `MIN_SET_MODELS` with clones counted once (`too_few_distinct_models`). `df.attrs["clones"]` is per horizon in `tests()` and per evaluator in `summary()`. Without clones all of it is the same call on the same columns, so such a table doesn't move by a bit. Same losses with other predictions are not clones, and raise or warn as they did. The kernels in `stats.py` don't know about clones. An average of three identical members can differ from them by rounding noise and then isn't a clone: `top=1` is exact.
- **Which keys:** pairs use their own common keys (`tests`, `compare`, `leaderboard`, DM columns), so one model with holes leaves other pairs untouched. Only `mcs`, `ranks` and the MCS columns use the keys of the whole set, and they print `n_days`, `n_forecasts` and which models limited them (`df.attrs["limited_by"]`). Never add a global intersection over all models of a report. Every comparison table prints `n_days` and `n_forecasts`.
- **Daily loss:** mean |error| over the periods of one (run_date, horizon) on the common keys, for whatever periods exist. `horizon="all"` averages those losses per run_date. `dm_test` takes daily means; `ratio_interval` takes daily error **sums**, so the interval agrees with the forecast-weighted ratio on DST days. With 24 periods on every day the two coincide and the numbers are evalproto's (`tests/test_report_evalproto.py`: z, p, ratio within 1e-10, intervals within 0.005, or exactly with the study's seed).
- **Per-hour DM is descriptive:** `tests(by="hour")` has no `p_holm`/`verdict`, and in groups cut by hour `DMEvaluator` leaves those two empty and `MCSEvaluator` its `in MCS`. Holm runs over the models of one horizon or group.
- **Test length is a span, `n_days` is observations.** `DailyLosses.span_days` / `PairComparison.span_days` are the calendar days from the first run date to the last. Only `short_test_message`, `warn_if_short` and `_flag_test_length` (the note below `FULL_TEST_DAYS`, the warning below `SHORT_TEST_DAYS`) read it; `MIN_VERDICT_DAYS`, `default_lag`, the bootstrap and `n_days` in every table stay observations, so 104 Fridays are `n_days` 104, lag 4 and no warning (`tests/test_issue_days_dm.py` pins the week-ahead study's DM statistics to 1e-10). With a forecast on every day the span is `n_days` and the message is word for word the old one.
- **No claim without data:** `verdict` and the confidence sets are empty below `MIN_VERDICT_DAYS` (30), intervals and rank uncertainty when the days fit in one block (`n_days <= block`), where every circular resample holds all of them. `verdict` is also empty when the test and the ratio point in opposite ways: the test weighs every day the same, the ratio every forecast. Days with only part of their periods in common go to `df.attrs["partial_days"]` with a warning. Mixed frequencies raise in `tests()` and the other methods, and in tables with a `SetEvaluator`; a table of plain metrics keeps working.
- **Bootstrap indices** are a function of `(n, block, reps, seed, kind)` (`bootstrap_indices`, cached), so a pair's interval doesn't depend on the other models in the table.
- **Battery:** `BatteryArbitrage.profit` is evalproto's Q5 rule, with `kind="stable"` sorts (the default sort's handling of ties depends on the CPU). `EconomicEvaluator` scores each model on its own whole days and counts a target day once across horizons; `profit days` prints how many. A whole day is judged by its period ids, not their number: a real run numbers periods by the clock (`hour` never exceeds 23, or 95), so a 23-hour day lacks one hour of 1-3; ids numbered through (0-22) look like a day without its last hour and count only on a Sunday. The frame's largest id says whether periods are hours or quarter-hours. A pipeline with it and `freq="1D"` raises in `run` (also `forecast_only`) and `report` before any model is planned (`ModelPipeline._check_evaluators_for`, decision 14), as `aggregate()` leaves it out. `tests/test_report_evalproto.py` pins it to `q4_metrics.csv`; `tests/test_comparison_report.py` runs real OLS models over both switches.
- **Counts per group.** Every `by_*` table, built by `_grouped_table` (the one place), has a `forecasts` column after its group keys, the model's own `len` of its frame in the group, finite or not, as in `summary()`; `metric_columns()` leaves it out (`_TABLE_KEYS`). `_flag_unequal_counts` warns once per table when the models of a group differ (a model with no row in a group counts 0, since it has no forecast there) and sets `df.attrs["unequal_counts"]` (group key tuples; no attribute without a difference). It compares counts, not keys: equal counts prove nothing, so relative metrics and tests still read the shared keys. `summary()` has the count and does not warn. `ExcelExporter` writes a `{sheet}_forecasts` sheet after the metric sheets of each breakdown (0 where a model has no row, every model's block on the groups of the whole table, no colours; the Summary sheet's colour scale leaves the count out); `TerminalExporter` prints the column. `tests/results/test_table_counts.py` holds it; `test_report_pin.py` pins the shape with the column.
- **Breakdowns, daily aggregates, join** (`results/breakdowns.py`, `EvaluationReport`): `by_quarter()`, `by_day()` and `by_price_level()` are `_grouped_table(...)` like the other `by_*`, with their grouping columns in `_BREAKDOWN_KEYS` (not in `GROUP_CONFIGS`, so `compute_all()` and the exporters keep their tables). The price level is read from `actual` only and the spike threshold from the actuals of all models together (each target date and hour once), never per model or from a prediction. `aggregate()` builds a new report of in-memory records with `freq="1D"`, `hour` 0 and a ref whose `skipped["incomplete_day"]` counts the dropped days; whole days come from `evaluators/_days.py` (`whole_days`), the one place that rule lives for `EconomicEvaluator` and `aggregate()`: don't write another. With a zone (`ModelResultRef.zone`: the frame's `index.tz`, or a manifest's `data_timezone` in `report()`, kept by `replace` and the ensembles' `_ref`) `aggregate()` keeps a day whose finite period ids are exactly those `clock_periods` gives its date (`clock_periods_on`, `daily_aggregate(clock=...)`), in place of `whole_days`, so a clock skipping midnight (Havana), 22:00 (Nuuk) or half an hour (Lord Howe) has its short day: the spring day is whole over 23 ids, every target day S+h of run S lacks one id and is dropped, the autumn day has 24 ids and a NaN actual and is dropped. A record of a slot the clock doesn't have isn't read at all (`ModelResultRef.iter_records`). Without a zone (plain lists, no manifest, a zone with no name, a naive index) it drops a day whose finite periods are fewer than the periods any model has a record for on that target date (any horizon), and a period no model has is taken at its word. Either way models are never aggregated over different hours of one day. `whole_days` and `EconomicEvaluator` don't look at the zone. A report whose results are `"1D"` builds its `LossPanel` with `whole_day_periods=(1,)`, or every day would count as partial. `join()` keeps the refs, takes the left evaluators and refuses name clashes and mixed frequencies.
- `tests/results/test_report_pin.py` pins the tables and exporter files of a report with only MAE, RMSE and rMAE, written by the code before set-level evaluators existed.
