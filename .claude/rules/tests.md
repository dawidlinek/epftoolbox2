# Tests

- No network in unit tests; mock the HTTP session. Real-API tests are `@pytest.mark.integration` and are excluded by `-m "not integration"`.
- Anything that runs a model: `monkeypatch.setenv("MAX_PROCESSES", "1")` and `monkeypatch.setenv("THREADS_PER_PROCESS", "1")`.
- Prefer synthetic data with a known answer (`tests/synthetic.py`) over hand-built frames: a generator with a seed, known coefficients and a local-time index spanning a DST switch.
- `tests/test_golden_metrics.py` pins current metric values on synthetic data. Refresh with `UPDATE_GOLDEN=1 uv run pytest tests/test_golden_metrics.py` only when a numeric change is intended, and say in the commit message why the numbers moved.
- Known methodology issues are pinned in `tests/test_known_issues.py` with `xfail(strict=True)`. Fixing one makes its test pass, which strict mode reports as a failure: remove the marker and move the test next to the code it covers.
- The fast suite runs in parallel (`pytest -n auto`, pytest-xdist): each worker is one process that runs its tests one after another, and which tests it gets changes from run to run. So a test owns its state. Every file goes under `tmp_path` and the working directory and environment variables are changed with `monkeypatch`, never a fixed path, port or cache directory; `tests/conftest.py` puts back the variables `Workflow.run()` sets for the whole process. The order a pool finishes days in is not fixed, so compare result files by their sorted lines (`lines()` or `Snapshot.sorted_records()` in the modules that have them), never by their bytes in file order. A module-scoped fixture is built once in every worker that runs one of the module's tests, so keep it cheap. After a change to a shared fixture or to anything process-wide, run the suite with another worker count and distribution (`-n 3 --dist loadfile`) to see a test that only passes next to the tests it used to run beside.
- Where one property is checked over a grid (switch x frequency x horizon x kind of list), cover every level of every axis and every pair of levels, not every cell. The identity tests in `test_validation_test.py` and `test_predictor_context.py` do this with half of the cells, and say so above the list of cells. A DST switch, the 15-minute frame, a horizon above 1 and a predictor function each stay in several cells.
- CSV fixtures are allowed under `tests/fixtures/` (everything else `*.csv` is gitignored).
- `tests/test_examples.py` runs each `examples/*.py` end to end through its `main(...)` on a short window against the live ENTSO-E, Open-Meteo and calendar sources. Every test there carries both `integration` (so `-m "not integration"` skips it) and `examples`, and uses the shared `entsoe_api_key` fixture (in `tests/conftest.py`, through `live_dir`), so it skips without a key; `test_lear_lago` needs none (`keyless_live_dir`: the benchmark comes from Zenodo, md5-checked, into `EpftoolboxBenchmarkSource`'s own cache). Run it with `ENTSOE_API_KEY=... uv run pytest -m examples -q` and put the key on the command line only. Each test works in `tmp_path` (the working directory, so the source cache and the output files land there) with one process and one thread.
- An example's `main(...)` takes the date ranges it uses and an output directory for the files it writes, and its defaults are the full run the script documents. Keep test-only code out of the examples: they are documentation first. When an example changes, update its test in the same commit.
- `tests/test_docs_code.py` checks every ```python block of README.md and `docs/src/content/docs/**` in the fast suite: it compiles the block, executes its `epftoolbox2` imports and binds each call to the real signature (calls on `x = Class(...)` variables and builder chains included). `reference/api.md` stubs are compared with the real signatures instead (every parameter, in order, with literal defaults). When a block fails, fix the docs. An import raising `MissingExtraError` for an extra that isn't installed is left unchecked (its names unresolved), so blocks importing `epftoolbox2.nets` are checked only where torch is installed (the `torch-extra` CI job). A block that is not runnable Python opts out with a meta string on its fence, ```` ```python nocheck ````, which Starlight ignores when it renders. Use it rarely: `MAX_OPT_OUTS` caps the number. Its two live tests (marker `examples`) run the README quick start and the docs Quick Start page block by block with the key from the environment and the dates shortened by explicit edits, which must keep matching the docs text.
- An example test asserts outcomes: the data frame (non-empty, key columns, no all-NaN column), `report.forecast_counts()` (no missing forecasts outside a DST window, identical forecast keys across models), that the issue-time check ran and found nothing where the example sets an issue time (`InformationSet.check` at `availability="raise"`, `InformationSet.late_uses` at `"warn"`; the `information_set_checks` fixture records both), and the files written.
